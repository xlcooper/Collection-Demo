# `data/` 运行数据目录说明

`data/` 是 Collection-Demo 在服务器上的运行工作区，用于保存输入图片、对象记忆库和实验产物。当前 Demo 数据固定在二十余张图片的小规模范围内，因此本目录全量由 Git 跟踪，便于本地与服务器共同审计、解释和清洗最终 Demo 结构。

## Git 管理边界

| 内容 | 是否进入 Git | 当前理由 |
|---|---|---|
| `data/README.md` | 是 | 说明目录用途、命名和保留策略 |
| 输入图片 | 是 | 当前数量有限，需要核对哈希、场景分组和 Demo 输入 |
| `memory.sqlite` | 是 | 需要拉取后检查对象、观测、候选和决策是否与报告一致 |
| crop、mask、overlay、对象参考图 | 是 | 需要直接检查候选质量、误建档和对象归并依据 |
| Qwen 原始响应与内部 run report | 是 | 需要审计模型原始判断、token、耗时和失败过程 |
| `environment/*.json` 精选验收报告 | 是 | 体积小、机器可读，是跨机器同步的验收证据 |
| `runs/` 阶段验证产物 | 是 | 先完整拉取，区分仍被流程依赖的资产和可删除的历史遗迹 |

当前采用“先完整纳管，再基于证据清洗”的策略：

1. 服务器先把现有 `data/` 与 `runs/` 原样提交，使本地能够看到完整事实。
2. 本地结合代码、SQLite、图片资产和报告解释每个目录的用途与依赖关系。
3. 确认功能后删除不再服务最终 Demo 的历史 gate、烟测和重复产物，只保留最终框架、固定 Demo 数据及必要证据。

Git 删除文件后仍保留历史版本，这是当前有意接受的审计能力，不作为本阶段体量阻塞。模型权重、缓存、项目 Conda 环境和根目录 `temp/` 中的隐藏真值仍保持忽略。

## 当前快照规模

服务器提交 `2cda2e0` 中，`data/` 共624个文件、276个子目录、约44.03 MiB。主要内容是245个 JPG、340个 PNG、5个 SQLite 记忆库、Qwen 原始响应和运行报告。

逐文件哈希核对后需要区分两种重复：

- `m5_input/` 中14对逐字节副本是端到端验收专门用于测试 SHA-256 幂等跳过的有效输入，不能按普通冗余删除；
- 记忆库将源图复制进 `sources/`，并将 proposal 资产复制到 object observation，这是当前可审计持久化设计的一部分，不能在活跃记忆库内部逐文件去重；
- `data/` 中15个 `.ipynb_checkpoints/` 目录的27个文件都与正式同级文件完全一致，共约1.56 MiB，代码和SQLite均不引用，属于明确的编辑器遗迹；连同 `runs/` 共28个检查点目录、48个重复文件、约7.40 MiB；
- `data/temp/` 与 `data/m5_input/` 的文件哈希多重集合完全相同，属于可清理的重复暂存副本。

## 记忆库根目录结构

`memory/`、`m5_qwen_gate_memory_01/`、`m5_validation_memory_01/` 等目录都采用相同结构。它们不是代码副本，而是彼此隔离的对象记忆数据库。

```text
<memory_root>/
├─ memory.sqlite
├─ sources/
├─ proposals/
├─ objects/
├─ raw_responses/
└─ run_reports/
```

| 路径 | 内容 | 是否可再生成 |
|---|---|---|
| `memory.sqlite` | `runs`、`source_images`、`proposals`、`objects`、`observations`、`decisions` 六类结构化索引和状态 | 不应单独重建；它是该记忆库的主索引 |
| `sources/` | 按 SHA-256 保存的规范源图副本 | 可从原始输入重新生成，但用于当前库审计 |
| `proposals/` | 按 run/proposal 保存的 `crop.png`、`mask.png`、`overlay.jpg` | 可重新推理生成 |
| `objects/` | 按 object/observation 保存的新建或归并对象观测资产 | 可重新运行生成，但与 SQLite 对象 ID 配套 |
| `raw_responses/` | Qwen 每次源图批量调用的原始文本、token、耗时和解析结果 | 可重新推理生成，但模型输出可能不完全一致 |
| `run_reports/` | 该记忆库内部保存的逐次运行报告 | 可由对应运行生成；精选报告另存到 `environment/` 进入 Git |

不要只复制或删除记忆库中的某一个子目录。`memory.sqlite` 与图像资产通过相对路径关联，迁移、归档或清理时应把整个 `<memory_root>/` 视为一个整体。

## 命名约定

| 模式 | 含义 | 示例 |
|---|---|---|
| `<purpose>_input/` | 某次验证的只读输入图片 | `m5_input/`、`m5_qwen_gate_input/` |
| `<purpose>_memory_<NN>/` | 某次独立实验的完整记忆库 | `m5_validation_memory_01/` |
| `memory/` | 默认或正式 Demo 记忆库 | `data/memory/` |

同一批图片需要重跑时，应使用新的编号记忆库，例如从 `_01` 改为 `_02`。复用旧库会触发 SHA-256 幂等门，使已经完成的图片直接跳过。

不要新建含义不明的 `temp/`、`test2/` 或 `new/` 作为正式实验目录。临时数据优先放到仓库根目录的 `runs/`，需要持久化的实验按上述命名。

## 保留与清理原则

- **正式记忆库**：按整体版本化和迁移，不拆分内部文件。
- **固定验收输入**：`m5_input/` 保留，14个副本用于哈希幂等门，不视为可清理重复。
- **本轮失败验收库**：`m5_validation_memory_01/` 整体保留为证据，不拆分、不覆盖，也不作为正式 Demo 初始库。
- **历史 gate 记忆库**：先提交并由本地审计；确认不再服务最终 Demo 后，在后续清洗提交中整目录删除。
- **编辑器与重复暂存遗迹**：`.ipynb_checkpoints/` 与 `data/temp/` 已完成内容核对，列入下一次经确认后的清理，不在本轮分析提交中删除。
- **未知目录**：先查看内容、大小、生成时间和引用关系，再决定；不得仅凭名称删除。
- **模型权重**：位于 `weights/`，不属于 `data/`，不要与实验产物一起清理。

本文件只描述目录用途。当前阶段、实验是否通过和下一动作以根目录 `PROGRESS.md` 为准。
