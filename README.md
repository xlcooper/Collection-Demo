# Collection Demo

> 从场景图片中自动发现物体、分割候选，并把跨视角观测组织成可审计的长期对象记忆。

Collection Demo 是一个端到端对象记忆研究 Demo。使用者不需要预先输入 `cup`、`mouse` 等类别词：系统先理解场景中值得观察的完整物体，再定位其实例、判断它与已有对象的关系，并将结果写入 SQLite 与配套图片资产。

项目同时提供 Web 实验台，用来管理输入和多份记忆库、运行完整实验、查看逐阶段证据，以及从“对象档案”和“候选血缘”两个角度检查最终记忆。

## 架构

```mermaid
flowchart LR
    A["当前场景图 + 已有对象文字摘要"] --> B["Qwen3-VL：发现、命名、文字身份假设与拟议摘要"]
    B --> C["SAM3：文本引导分割"]
    C --> D["DINOv3：CLS + mask 内 patch 视觉指纹"]
    D --> E["Qwen 假设与视觉证据一致性决定"]
    E --> F["SQLite 对象摘要、观测与血缘"]
```

Qwen3-VL、SAM3 与 DINOv3 在单张 GPU 上联合驻留，并按图片逐张完成闭环。每张唯一新图只调用一次 Qwen：它读取当前原图和已有对象的文字摘要，既提出分割目标，也给出文字身份假设和拟议的对象摘要；随后 SAM3 生成候选，DINOv3 用当前候选与历史视角指纹比较。只有文字假设与视觉证据满足提交规则时，系统才新建对象或迭代原有摘要。

## 工作原理

| 阶段 | 通俗解释 | 关键技术 |
|---|---|---|
| 发现与文字建档 | 按图片内容去重；Qwen 结合当前图和已有文字摘要提出完整物体、类内区别特征、身份假设与拟议摘要 | SHA-256、Qwen3-VL、结构化单次输出 |
| 分割 | 将每个目标的英文检索短语原样交给 SAM3；同图相同短语只查询一次，再用临时框把目标与 mask 一对一对应 | 文本引导分割、置信度与几何过滤、框重合度 |
| 视觉身份 | 为候选生成全局 CLS 和 mask 内局部 patch 指纹，与对象的历史视角指纹比较 | DINOv3、余弦相似度、局部对应、歧义差距 |
| 决定与记忆 | 对齐 Qwen 身份假设和 DINOv3 证据；一致时写入 `new/existing`，冲突时保留 `uncertain` | 可解释双证据规则、SQLite 事务、相对路径资产 |

Qwen 输出的中文名称、当前可见事实和对象摘要用于语义记忆；真正送入 SAM3 的只有英文 `sam_text_prompt`。DINOv3 不负责命名、读品牌或写描述，只提供图像到图像的身份证据。对象卡只保留一份持续迭代的文字摘要；crop 与 mask 供页面展示和审计，自动历史比较只读取视觉指纹。

## Web 实验台

Web 页面围绕一次真实实验组织，而不是只展示最终数字：

- 浏览、上传和删除输入图片，并明确显示内容去重结果；
- 新建独立记忆库，或在一份完整的已有记忆库中继续加入新观测；
- 按真实落盘事件显示阶段进度、总耗时和中间结果；
- 对照查看 Qwen 文字身份假设、SAM3 定位/裁剪/掩码、DINOv3 视觉证据和最终决定；
- 以长期对象卡、跨视角观测时间线和候选血缘查看 SQLite 记忆；
- 汇总本次增量、库内累计、运行错误与需要人工复核的结果。

实验运行期间，输入和记忆库管理会被锁定；失败或不完整的记忆库只供复核和整库删除，避免在不完整状态上继续写入。

## 快速开始

项目面向 Linux + NVIDIA GPU 服务器，使用 Conda 管理环境。完整的依赖安装、模型准备与服务器检查见[服务器环境搭建指南](docs/03_服务器环境搭建指南.md)。

准备好项目环境与模型缓存后：

```bash
conda activate "$PWD/.conda/envs/object-memory-demo"
export HF_HOME="$PWD/weights/qwen"
export HF_HUB_CACHE="$HF_HOME/hub"
```

启动 Web 实验台：

```bash
python scripts/run_object_memory_web.py --host 127.0.0.1 --port 6006
```

进入页面后先点击“新建空白库”；仓库内现有 `data/memory/` 是旧流程的历史实验，只读展示，不会自动迁移到新 schema。

如果通过 AutoDL 的 HTTPS 自定义服务访问，该网址可能被其他电脑访问，即使程序监听的是 `127.0.0.1`。请先设置至少12字符的密码，再启动相同命令：

```bash
export OBJECT_MEMORY_WEB_PASSWORD='<至少12字符的强密码>'
python scripts/run_object_memory_web.py --host 127.0.0.1 --port 6006
```

浏览器认证用户名默认为 `object-memory`。不要把没有 HTTPS 或其他安全入口保护的原始 HTTP 服务直接暴露到公网。

也可以直接运行命令行实验：

```bash
python scripts/run_object_memory.py \
  --input-dir data/input \
  --memory-root data/memory_dinov3_first \
  --validate-demo \
  --report environment/run_report_dinov3_first.json
```

完整参数、全新实验与增量续写方式见[业务代码运行与验证指南](docs/04_业务代码运行与验证指南.md)。

## 结果与审计

一份对象记忆库由 `memory.sqlite`、源图副本、候选展示资产、DINOv3 指纹、Qwen 原始响应和内部运行报告共同组成。数据库保存它们之间的结构化关系，资产使用相对路径关联，因此整份记忆库必须作为一个单元迁移、提交或删除。

Web 提供两种互补视角：

- **对象卡与观测时间线**回答“这个长期对象在不同图片中被看到了几次，信息是否稳定”；
- **候选血缘**回答“某张源图经过什么提示、分割、过滤和判断，最终进入了哪个对象”。

结构检查通过只说明流程和数据关系完整，不代表物体发现、分割或身份判断在语义上一定正确。Qwen 没有提出的物体不会进入 SAM3；同类别、颜色或材质也不能单独证明两次观测属于同一具体实例。DINOv3 的同类日用品实例匹配阈值仍需用后续同类实例数据标定，因此当前 Demo 保留 `uncertain` 与人工复核入口。

## 范围

Collection Demo 聚焦“被动场景图片 → 可审计对象记忆”这一最小闭环。它尚不包含主动采集、视角规划、机械臂控制、认知完整度或世界模型；当前能力边界与最新实验证据以 [PROGRESS.md](PROGRESS.md) 为准。
