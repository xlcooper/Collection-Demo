# Collection-Demo

> **项目管理入口（强制）**：每个新对话必须先读本文件，再读 `PROGRESS.md`。README 只保存项目摘要、长期准则和文件导航；`PROGRESS.md` 是当前阶段、完成状态、执行计划和下一动作的唯一事实源。不得从 README、CHANGELOG 或初始规划书推测当前进度。每次收到服务器结果、调整依赖或推进阶段后都要同步维护 PROGRESS、相关职责文件和 CHANGELOG；用户说明服务器已 push 时，本地 AI 必须先 `pull`。

**第一阶段摘要目标**：给系统一批不断增加的场景图片，它能自动发现物体、生成标签、建立对象档案，并把同一具体物体的不同观测持续归并到同一档案中。第一阶段暂不负责主动选择拍摄视角、控制机器人或判断物体信息是否已经完整。

- **当前版本**：v0.10.3
- **当前阶段**：M5-A——无外部类别提示的 SAM3 自动候选校准
- **当前状态摘要**：首次真实场景校准覆盖了 3/3 个物体，但 12 个保留候选中有 9 个桌面、阴影或局部噪声；已增加大区域和被完整候选包含的局部 mask 过滤，等待同图复验
- **权威进度与下一步**：查看 `PROGRESS.md`

## 当前范围

第一阶段计划实现以下无人值守 workflow：

```text
输入场景图片目录
→ 计算图片 SHA-256，跳过已经处理的图片
→ 项目脚本在整张图上自动铺设采样点（用户不提供物体类别）
→ SAM3 根据每个采样点产生 mask 候选
→ 后处理过滤低置信、过小/过大、重复、被完整候选包含的局部和超量候选，并生成 crop、mask、overlay
→ 释放 SAM3 显存
→ 从 SQLite 读取已有对象卡片
→ Qwen 比较当前候选与已有对象，并输出受约束 JSON
→ 校验 JSON
    ├─ new：生成标签，创建对象并保存首次观测
    ├─ existing：归入已有对象并追加观测
    ├─ ignored：记录无效原因
    └─ uncertain：进入 pending 并按规则重试
→ SQLite 事务写入
→ 输出本次运行摘要
```

本阶段不实现认知完整度、主动视角规划、机械臂控制、空间地图或完整世界模型。

当前第一阶段端到端实验总入口是 `python scripts/run_object_memory.py`；`scripts/verify_m*.py` 只用于分阶段验证和问题定位，不是正式总入口。

## 当前技术决策

- SAM3 官方图像 checkpoint；Qwen3-VL-8B-Instruct-FP8 首选，4B 仅作实测失败后的回退。
- 主业务流程采用无类别提示的自动点网格候选；SAM3 本身没有官方“一键列出所有物体”接口，因此候选覆盖率必须通过服务器场景图实测校准，不能把自动候选表述成绝对穷举。
- 单卡顺序加载两个模型；Transformers 直接推理，不引入推理服务。
- 文件系统保存图像资产，SQLite 保存结构化索引。

完整环境事实、模型选择和风险只在 `docs/02_服务器环境分析.md` 维护。

## 长期开发准则

本节是所有新对话和后续开发必须优先读取并持续遵守的规则。用户可以明确扩展准则；新增规则应写入本节或相应职责文件，并记录到 CHANGELOG。

1. **PROGRESS 权威**：每个新对话按 README → PROGRESS → 当前任务相关文件的顺序读取。初始纲要和规划书提供设计依据，但真实进度、计划修正和下一步只写入 PROGRESS。
2. **MVP 与奥卡姆剃刀**：优先完成满足当前目标的最小方案，避免额外扩展、过早抽象和过度设计。
3. **聚焦第一阶段**：当前只开发自动化对象记忆 Demo；主动采集、视角规划、机械臂和世界模型均不提前实施。
4. **Friendly 代码**：模块、脚本和逻辑必须职责清楚、命名直接、流程可读；优先短函数、显式类型、结构化模型输出和可操作错误信息。
5. **本地/服务器分工**：本地只用于人与 AI 协作、修改、审查、提交和 push；不在本地安装深度学习环境或运行脚本/测试。所有脚本、测试与 Demo 只在 AutoDL 服务器执行。
6. **Conda 与依赖管理**：项目运行环境统一由 Conda 管理；Conda 基础环境以 `environment.yml` 为事实源，Python 依赖以 `requirements*.txt` 为事实源，不把临时安装命令当作最终配置，不长期使用 `base` 环境运行项目。环境配置按可独立重跑的步骤拆分，不使用单个脚本串联全量安装。
7. **显式脚本入口**：从后续新增功能开始，面向用户的运行入口统一写成 `python scripts/<脚本名>.py [参数]`。Git 负责同步项目代码；依赖安装只在首次配置或依赖变化时单独说明，不得混入每次运行步骤。不得新增依赖 `pip install -e .` 才能使用的控制台快捷命令；现有 M1/M2 入口不为此返工。
8. **事实优先，禁止臆测**：任何涉及环境、依赖、模型、缓存或文件路径的设计与实现，必须先查阅对应职责文档、最新服务器报告和已经验证通过的脚本。不得用框架默认值、个人经验或未经验证的假设替代项目事实；信息冲突或证据不足时，应先核查并明确标注不确定性，必要时向用户确认，再继续开发。
9. **Git 与服务器先验**：用户通知服务器已 push 后，本地 AI 必须首先 pull，并只依据拉取到的结果文件分析。用户可以只提交服务器生成的报告，不负责维护 CHANGELOG。
10. **职责化维护**：真实代码和最新服务器结果发生变化时，同一批次直接对齐 README 当前摘要、PROGRESS 和受影响的职责文件；过时描述应替换，不得靠追加说明保留多个“当前版本”。初始规划书、历史报告和 CHANGELOG 不回写，只保留其原始历史含义。每类信息只在一个职责文件详细维护，其他文件只做摘要和链接。
11. **Push 规则**：每个完成的本地 AI 修改批次都必须更新 CHANGELOG、提交并 push；若 push 失败必须明确报告。
