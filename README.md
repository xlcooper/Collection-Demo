# Collection-Demo

> **维护规则（强制）**：本文件是项目当前状态的唯一入口。每次收到服务器结果、调整依赖或推进阶段后，本地 AI 必须先 `pull`，再在同一维护批次更新当前状态、下一步、导航和 CHANGELOG；已经失效的结论必须替换，不得继续作为“当前信息”保留。若摘要与最新服务器报告冲突，以报告为准并立即修正文档。

第一阶段自动化对象记忆 Demo：SAM3 发现并分割场景物体，MLLM 判断对象新颖性、生成结构化标签，并把同一具体物体的多次观测归并至显式记忆库。

- **当前版本**：v0.3.2
- **当前阶段**：M0——模型冒烟验证
- **当前状态**：服务器基础环境无阻塞，Qwen 权重已下载；SAM3 使用具体类别提示已由用户确认运行通过，报告待回传；下一步验证 Qwen3-VL

## 当前范围

```text
场景图像 → SAM3 候选、mask 与 crop
        → MLLM 新颖性判断和自动标注
        → 新建对象 / 归并已知对象 → 显式对象记忆库
```

本阶段不实现认知完整度、主动视角规划、机械臂控制、空间地图或完整世界模型。

## 当前技术决策

- **视觉模型**：官方 `facebook/sam3` 图像 checkpoint。
- **SAM3 权重**：服务器 `weights/sam3/sam3.pt`，仅服务器保留并由 Git 忽略。
- **MLLM 首选**：`Qwen/Qwen3-VL-8B-Instruct-FP8`。
- **MLLM 回退**：`Qwen/Qwen3-VL-4B-Instruct`，仅在 8B FP8 实测失败时启用。
- **运行方式**：先运行 SAM3 并保存中间结果，释放模型后再运行 MLLM；两个模型不同时驻留显存。
- **推理框架**：MVP 使用 Transformers 直接推理，不引入 vLLM/SGLang 服务。
- **存储方式**：文件系统保存图像资产，SQLite 保存结构化索引。

## 长期开发准则

本节是所有新对话和后续开发必须优先读取并持续遵守的规则。用户可以明确扩展准则；新增规则应写入本节或相应维护章节并记录到 CHANGELOG。

1. **MVP 与奥卡姆剃刀**：优先完成满足当前目标的最小方案，避免额外扩展、过早抽象和过度设计。
2. **聚焦第一阶段**：当前只开发自动化对象记忆 Demo；主动采集、视角规划、机械臂和世界模型均不提前实施。
3. **Friendly 代码**：模块、脚本和逻辑必须职责清楚、命名直接、流程可读；优先短函数、显式类型、结构化模型输出和可操作错误信息。
4. **本地/服务器分工**：本地只用于人与 AI 协作、修改、审查、提交和 push；不在本地安装深度学习环境或运行脚本/测试。所有脚本、测试与 Demo 只在 AutoDL 服务器执行。
5. **Conda 与依赖管理**：项目运行环境统一由 Conda 管理；Conda 基础环境以 `environment.yml` 为事实源，Python 依赖以 `requirements*.txt` 为事实源，不把临时安装命令当作最终配置，不长期使用 `base` 环境运行项目。环境配置按可独立重跑的步骤拆分，不使用单个脚本串联全量安装。
6. **Git 与服务器先验**：用户通知服务器已 push 后，本地 AI 必须首先 pull，并只依据拉取到的结果文件分析。用户可以只提交服务器生成的报告，不负责维护 CHANGELOG。
7. **持续维护**：本地 AI 负责 README、PROGRESS、CHANGELOG 和状态型文档。每次服务器结果、依赖变化或阶段推进后，必须更新其中的依据时间、当前结论、里程碑证据和下一步；过时内容应替换或明确归档，不能继续产生误导。
8. **Push 规则**：每个完成的本地 AI 修改批次都必须更新 CHANGELOG、提交并 push；若 push 失败必须明确报告。

## 版本规则

- CHANGELOG 由本地 AI 统一维护；用户的服务器结果提交允许暂不更新 CHANGELOG，由 AI 在拉取和分析后的维护提交中补记。
- 每个 AI push 在 CHANGELOG 顶部增加语义化版本号、北京时间时间戳和简短摘要。
- 默认递增补丁版本；阶段目标或兼容性明显变化时递增次版本或主版本。
- 同一对话回合中的关联修改作为一个版本批次提交。
