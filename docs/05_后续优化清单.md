# 后续优化清单

> 本文档集中保存用户明确延后项、用户记录的后续想法、有证据但待定优先级的假设、已接受权衡和历史不处理项。它不是当前版本计划，也不用来判定当前实验是否通过。

## 管理规则

- 每项使用稳定 ID；普通版本升级不删除、重置或重新排号。
- 只记录用户已提出的后续想法、已明确延后的事项，或有实验证据但当前未排期的事项。
- 条目状态只在用户改变优先级、开始实施、实验证实或明确放弃时更新。
- 当前必须修复的阻断项仍写在 `AGENTS.md`；已发生事实和审计结论仍写在 `PROGRESS.md`。

- **记录依据**：2026-08-06至2026-08-07，用户明确区分“类间区别”和“类内区别”，指出当前鼠标描述只有类别共有特征，不能区分多个相似银灰色鼠标。
- **确认方向**：SAM3先自动提出候选，DINOv3先组织跨图视觉聚类；Qwen按聚类接触表和已有对象文字摘要输出完整性判断、身份假设与对象汇总文本。历史DINOv3证据和Qwen一致才提交 `new/existing` 与新摘要，冲突时保留原摘要并写入 `uncertain`，不再调用第二次Qwen。
- **文本边界**：每个对象只保留一份持续迭代的对象级汇总文本；品牌、标识、非对称结构、比例和部件布局等稳定类内特征按可见证据累计，颜色和材质必须与具体部件关联。
- **尚未证明**：当前固定输入每个类别只有一个具体实例，不能证明该设计已经能够区分同类不同实例。

### FUT-VEC-001 DINOv3视角视觉指纹

- **状态**：用户已在服务器下载固定模型；v0.22.0 已实现 CLS、mask 内 patch、NPZ 存储、跨图候选聚类、历史全局粗排、局部比较和歧义决定，尚未完成服务器运行与阈值标定。详细验收书见根目录 `DEMO自动候选视觉聚类优化方案.md`。
- **确认方向**：首版只使用 `facebook/dinov3-vitb16-pretrain-lvd1689m`，为每个SAM3候选保存CLS全局指纹和mask内patch局部指纹；本轮候选聚类使用CLS，历史身份比较使用全局+局部指纹，均不读取历史crop或mask。
- **存储边界**：第一版不保存文本向量和对象原型向量，不引入向量数据库；直接比较对象的历史视角指纹。crop和mask只在生成指纹时使用一次，之后作为对象卡和候选审计的展示证据。
- **决策边界**：DINOv3只提供图像对图像的视觉证据，不能输出类别、品牌或对象摘要；其论文中的实例检索结果不能代替本项目的同类日用品实验。

### FUT-CLU-001 DINOv3候选聚类阈值与组内一致性

- **状态**：v0.22.0 已实现，等待固定输入与同类实例实验。
- **记录依据**：2026-08-07 用户提出“SAM一次产生较多候选，然后DINO对所有候选聚类、去重”，并确认无用候选可以先经脚本去重再由DINO整理。
- **当前行为**：不同source候选按CLS余弦相似度阈值0.75受约束合并；同一source的两个候选禁止进入同一聚类；聚类只作为Qwen审查单元，不删除成员观测。
- **尚未证明**：默认阈值是否会把相似同类实例误合并、把同一实例不同视角误拆分，以及单一连接式合并是否会产生低一致性长链。
- **后续方向**：用隐藏实例真值统计误合并/误拆分和组内最低相似度，再决定阈值或聚类算法；没有实验前不增加复杂聚类器。

## 当前接受的设计权衡

### FUT-BATCH-001 Qwen聚类批次权衡

- **状态**：v0.22.0 已改为最多8个聚类一次Qwen，等待服务器验证调用数、耗时和批次失败边界。
- **记录依据**：2026-07-31 用户明确要求保留4图批次设计和其 trade-off；v0.17.0 的6词错误和 v0.17.4 的旧 `and` 误判都证明了单字段错误会使同批4张图一起停止。两个已知硬限制现已分别修正。
- **当前行为**：`max_clusters_per_batch=8`；一个批次结构化响应失败会明确终止该批次及后续聚类，不拆单、不重试。下一批次可读取前一批已提交的新对象摘要和历史指纹，同一批内则共享调用前快照。
- **后续方向**：通过服务器报告比较聚类数、批次数、Qwen token/耗时和失败影响范围。
- **权衡**：大批次降低调用和重复上下文成本，但一个字段错误影响整批，且同批聚类不能使用批内刚创建的对象；小批次相反。

### FUT-DISC-001 自动候选的召回与精度

### FUT-SAM-001 SAM3点提示质量阈值的召回与误检

- **状态**：v0.22.0 恢复历史点网格质量阈值0.88，等待服务器实验验证。
- **记录依据**：v0.17.4中进入SAM3的16条提示有5条返回0候选，且一个成功水瓶候选分数仅约0.531，说明0.5可能偏紧；阈值前的最高失败分数没有被官方接口保留，因此不能保证0.4一定找回这些物体。
- **当前行为**：每个网格点只保留多mask输出中的最高分mask，脚本只接受质量分不低于0.88的候选；报告记录原始点候选、保留/过滤数与原因。

- **权衡**：较低阈值可能找回遮挡或弱候选，也会增加背景区域、重复候选、DINO计算和聚类审查成本。
