# 服务器环境与模型冒烟测试指南

## 1. 目的

本指南用于在 AutoDL 服务器上创建可复现的项目环境，并分别验证 SAM3 与 Qwen3-VL 的真实推理链路。所有命令均在服务器仓库目录执行。

默认路径：

```text
仓库：/root/autodl-tmp/Collection-Demo
环境：.conda/envs/object-memory-demo
SAM3 权重：weights/sam3/sam3.pt
Qwen 缓存：weights/qwen
```

SAM3 权重和 SAM3 Python 源代码是两个独立组成部分：现有 `sam3.pt` 无需重复下载，但仍需安装源码才能加载并运行权重。

## 2. 依赖文件

| 文件 | 职责 |
|---|---|
| `environment.yml` | 只创建 Python 3.12 和基础 Conda 环境 |
| `requirements.txt` | 安装 PyTorch cu128、Qwen 和普通 Python 依赖 |
| `requirements-sam3.txt` | 单独安装 SAM3 固定提交的源码 |

三个步骤相互独立，某一步因网络失败时只重跑该步，不重新执行全部安装。

## 3. 配置环境

### 3.1 准备仓库并关闭全局网络加速

```bash
cd /root/autodl-tmp/Collection-Demo
git pull origin main
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY all_proxy
```

AutoDL 的 `network_turbo` 只在安装 SAM3 源码时使用，不应用于 Conda 或普通 pip 源。

### 3.2 创建或更新 Conda 基础环境

首次创建：

```bash
conda env create \
  --prefix "$PWD/.conda/envs/object-memory-demo" \
  --file environment.yml
```

如果目录已经存在，则使用更新命令：

```bash
conda env update \
  --prefix "$PWD/.conda/envs/object-memory-demo" \
  --file environment.yml
```

激活环境：

```bash
conda activate "$PWD/.conda/envs/object-memory-demo"
```

### 3.3 安装普通 Python 依赖

```bash
python -m pip install \
  --timeout 120 \
  --retries 10 \
  -r requirements.txt
```

该步骤不启用 `network_turbo`。第一阶段不安装 `flash-attn-3` 或 `cc_torch`，避免系统 nvcc 11.8 影响基础链路。

### 3.4 单独安装 SAM3 源码

```bash
source /etc/network_turbo
python -m pip install \
  --no-deps \
  --no-build-isolation \
  --timeout 120 \
  --retries 10 \
  -r requirements-sam3.txt
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY all_proxy
```

`--no-deps` 和 `--no-build-isolation` 保证开启加速后只下载 GitHub 上的 SAM3 源码，不访问普通 pip 源。SAM3 当前仍导入 `pkg_resources`，所以基础环境将 `setuptools` 限制为 81 以下。实际图像导入链需要但官方基础依赖未列出的 `einops` 和 `pycocotools` 已显式写入 `requirements.txt`。安装失败时只重跑本小节。

### 3.5 创建运行目录并自检

```bash
mkdir -p data weights/qwen
export OMP_NUM_THREADS=8
python scripts/check_server_env.py \
  --model-dir weights \
  --data-dir data \
  --sam3-checkpoint weights/sam3/sam3.pt
```

自检结果写入 `environment/server_env_report.json`。若 `summary.status` 为 `blocked`，先提交报告并分析，不继续冒烟测试。

旧版本曾创建 `weights/huggingface`。如果它为空可以删除；如果其中已有 Qwen 下载内容，可在没有下载任务运行时将其重命名为 `weights/qwen`。

## 4. 准备冒烟图像

选择一张包含至少一个清晰独立物体的 JPG 或 PNG，保存到被 Git 忽略的数据目录，例如：

```text
/root/autodl-tmp/Collection-Demo/data/smoke/scene.jpg
```

## 5. 顺序运行两个冒烟测试

```bash
cd /root/autodl-tmp/Collection-Demo
bash scripts/run_server_smoke_tests.sh \
  /root/autodl-tmp/Collection-Demo/data/smoke/scene.jpg \
  object
```

第二个参数 `object` 只验证 SAM3 文本提示链路，不代表最终的“全量发现”策略。运行器会启动两个独立 Python 进程：SAM3 结束并释放显存后，才会加载 Qwen3-VL。

## 6. 输出与通过条件

建议提交至 Git 的小型报告：

```text
environment/server_env_report.json
environment/sam3_smoke_report.json
environment/qwen_smoke_report.json
```

被 Git 忽略的大型或临时产物：

```text
runs/smoke/**
weights/**
.conda/**
data/**
```

通过条件：

- 环境：Python 3.12、PyTorch CUDA 可用、SAM3 可导入、checkpoint 存在；
- SAM3：生成至少一个 proposal、mask，并记录耗时和显存；
- Qwen3-VL：生成可解析的 JSON，七个必填字段齐全，并记录耗时和显存。

## 7. 回传结果

运行完成后，在 CHANGELOG 顶部增加新的补丁版本摘要，再提交三份报告：

```bash
git add CHANGELOG.md \
  environment/server_env_report.json \
  environment/sam3_smoke_report.json \
  environment/qwen_smoke_report.json
git commit -m "chore: record server smoke results"
git push origin main
```

报告 push 后，本地 AI 首先 pull，再分析结果并决定是否进入 M1。
