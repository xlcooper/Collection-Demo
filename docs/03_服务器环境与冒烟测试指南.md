# 服务器环境与模型冒烟测试指南

> **维护规则（强制）**：本文只维护服务器环境重建与 SAM3/Qwen 冒烟复现命令，不承担当前业务开发任务或里程碑管理。环境、路径、模型或依赖变化后，本地 AI 必须同步更新相关步骤；失效命令应替换，不得靠不断追加补丁说明维持。发生冲突时，以 `environment.yml`、`requirements*.txt` 和最新服务器报告为准；当前开发任务以 `PROGRESS.md` 为准。涉及环境、模型、缓存或路径的代码开发前，必须先读 `docs/02_服务器环境分析.md` 和本文，并对照已验证脚本，不得假定框架默认路径就是项目路径。

## 1. 当前入口

项目当前阶段和下一动作只以 `PROGRESS.md` 为准；服务器状态、模型决策和全部确认路径只以 `docs/02_服务器环境分析.md` 为准。本文不重复维护这些事实，只提供环境重建和模型验证的可执行命令。

执行本文命令前必须先核对 `docs/02_服务器环境分析.md` 的“当前确认路径”。命令中出现的路径用于实际操作，不构成第二份路径事实源；若服务器路径变化，应先更新 `docs/02`，再同步修改本文命令。

## 2. 环境重建步骤

本节仅用于新服务器或环境损坏后的重建。当前服务器无需执行。

### 2.1 Conda 基础环境

```bash
cd /root/autodl-tmp/Collection-Demo
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY all_proxy

conda env create \
  --prefix "$PWD/.conda/envs/object-memory-demo" \
  --file environment.yml

conda activate "$PWD/.conda/envs/object-memory-demo"
```

环境已存在时，将 `conda env create` 换成：

```bash
conda env update \
  --prefix "$PWD/.conda/envs/object-memory-demo" \
  --file environment.yml
```

### 2.2 普通 Python 依赖

```bash
python -m pip install --timeout 120 --retries 10 -r requirements.txt
```

### 2.3 SAM3 源码

已有 `sam3.pt` 只是权重，仍需安装源码。网络加速只用于这个 GitHub 步骤：

```bash
source /etc/network_turbo
python -m pip install \
  --no-deps \
  --no-build-isolation \
  --timeout 120 \
  --retries 10 \
  -r requirements-sam3.txt
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY all_proxy
```

三个步骤相互独立，哪一步失败只重跑哪一步。

## 3. 拉取最新维护版本并自检

```bash
cd /root/autodl-tmp/Collection-Demo
git pull origin main
conda activate "$PWD/.conda/envs/object-memory-demo"
export OMP_NUM_THREADS=8
mkdir -p data/smoke weights/qwen

python scripts/check_server_env.py \
  --model-dir weights \
  --data-dir data \
  --sam3-checkpoint weights/sam3/sam3.pt
```

自检写入 `environment/server_env_report.json`。增强版自检会真实导入 SAM3，避免只检查“包名存在”造成假通过。

## 4. 下载 Qwen 权重

在项目环境中执行：

```bash
export HF_HOME="$PWD/weights/qwen"
export HF_HUB_CACHE="$HF_HOME/hub"
source /etc/network_turbo
hf download Qwen/Qwen3-VL-8B-Instruct-FP8
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY all_proxy
```

`weights/qwen` 是 Hugging Face 缓存根目录，实际模型位于其 `hub/` 子目录。下载中断后重复同一条 `hf download` 命令即可复用缓存并继续。

## 5. 准备测试图像

选择一张包含至少一个清晰独立物体的 JPG 或 PNG，保存为：

```text
/root/autodl-tmp/Collection-Demo/data/smoke/scene.jpg
```

当前小规模 Demo 的测试图像与 `runs/` 过程产物由 Git 跟踪，便于跨机器审计和最终结构清洗；模型权重与缓存仍由 Git 忽略。

## 6. 按需复现冒烟测试

SAM3 已运行通过；只有需要复现或更换测试图像时才重跑。脚本要求传入与图像中目标匹配的具体单数英文类别，并在推理阶段使用 RTX 4090 支持的 BF16 autocast：

```bash
python scripts/smoke_sam3.py \
  --image data/smoke/scene.jpg \
  --checkpoint weights/sam3/sam3.pt \
  --prompt cup \
  --output-dir runs/smoke/sam3 \
  --report environment/sam3_smoke_report.json
```

将示例中的 `cup` 替换为测试图像中清晰存在的类别，例如 `bottle` 或 `can`。该命令只复现环境层的提示分割冒烟，不代表当前业务候选策略，也不证明全量物体发现；当前业务总入口见 `docs/04_业务代码运行与验证指南.md`。

Qwen3-VL 单模型已通过；只有复现时才单独运行：

```bash
export HF_HOME="$PWD/weights/qwen"
export HF_HUB_CACHE="$HF_HOME/hub"

python scripts/smoke_qwen.py \
  --image data/smoke/scene.jpg \
  --model Qwen/Qwen3-VL-8B-Instruct-FP8 \
  --output-dir runs/smoke/qwen \
  --report environment/qwen_smoke_report.json
```

脚本默认读取 `HF_HUB_CACHE`，把模型缓存的 `refs/main` 解析到 `snapshots/<commit>`，再将该本地目录传给 Transformers；这避免仓库 ID 路径继续请求 Hub API。只有需要脚本自行联网取文件时才显式增加 `--allow-network`；正常冒烟不要使用该选项。

模型、依赖或服务器发生变化时，使用具体 SAM3 提示重新验证顺序运行：

```bash
bash scripts/run_server_smoke_tests.sh data/smoke/scene.jpg cup
```

将 `cup` 替换为图像中的实际类别。顺序脚本不再提供 `object` 默认值，以避免产生误导性失败。

统一入口会自行激活项目 Conda 环境并设置 `OMP_NUM_THREADS`、`HF_HOME` 和 `HF_HUB_CACHE`，随后依次运行两个模型和环境自检；新终端也无需手动逐条 `export`。日常 M1 开发无需重复冒烟，只有模型、依赖或服务器变化时才重跑。

## 7. 通过条件

- 环境：0 个阻塞项；nvcc 11.8 警告可以保留；
- SAM3：`proposal_count > 0`，至少保存一个 mask，并记录耗时和显存；
- Qwen3-VL：输出可解析 JSON，七个必填字段齐全，并记录耗时和显存；
- 存储：Qwen 下载和冒烟后仍有足够空间保存首批 Demo 数据。

建议提交至 Git 的小型报告：

```text
environment/server_env_report.json
environment/sam3_smoke_report.json
environment/qwen_smoke_report.json
```

模型权重、缓存和项目 Conda 环境继续由 Git 忽略；当前小规模 Demo 的 `data/` 与 `runs/` 由 Git 跟踪。

## 8. 回传规则

用户提交本轮生成或变化的报告，以及对应的 `data/`、`runs/` 产物；无需编辑 CHANGELOG：

```bash
git status --short
git add environment/server_env_report.json \
  environment/sam3_smoke_report.json \
  environment/qwen_smoke_report.json \
  data/smoke \
  runs/smoke
git commit -m "chore: record server smoke results"
git push origin main
```

不存在的报告不要加入 `git add`。用户通知 push 完成后，本地 AI 必须先 pull，再负责分析、更新 README/环境文档、补记 CHANGELOG 并 push 维护提交。
