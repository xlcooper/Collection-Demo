# AutoDL 服务器环境分析

> 本文维护当前服务器环境、模型路径和部署约束。环境事实来自 `environment/server_env_report.json`；对象记忆实验与审计结论见 `PROGRESS.md`，当前协作方向见 `AGENTS.md`。

## 当前结论

现有 AutoDL 单卡环境可以运行 Collection-Demo，无需重建 Conda 环境或更换模型。SAM3与Qwen3-VL已在最新运行 `run_20260803T093048019080Z` 中依次完成真实推理，顺序驻留的峰值显存低于RTX 4090 24 GiB容量。该运行结构通过但语义覆盖只有15/24，失败边界来自首轮用词和SAM3召回，不是服务器环境故障。

当前 `data/memory/` 与 `environment/run_report.json` 保存上述最新运行的完整证据；报告实际使用首轮v4、第二轮v3、SAM3阈值0.4和原色候选上下文。当前代码随后升级为首轮v5（基础类别优先，至多一个有用前置修饰词），尚未由新运行复验。v0.17.4及更早的已删除实验可从Git提交 `f413654` 恢复。

Qwen 必须使用项目数据盘中的 Hugging Face 缓存，不能回退到系统默认缓存。模型权重、缓存和项目 Conda 环境均不进入 Git。

## 模型部署

### SAM3

- 使用官方图像 checkpoint；
- 由首轮 Qwen 生成的受约束文本概念提供提示；
- 当前优先使用短而稳定的完整物体类别，文字置信度阈值为0.4；
- 同一源图编码一次，再逐概念调用高层 processor；
- 候选后处理在 CPU 可审计数据结构上完成；
- 不安装视频、训练或可选 CUDA 扩展。

### Qwen3-VL

- 使用 `Qwen/Qwen3-VL-8B-Instruct-FP8`；
- 从项目本地 snapshot 加载；
- 使用 Transformers 直接推理；
- 分别承担 SAM3 前的场景观察和 SAM3 后的候选/记忆判断；
- 不引入 vLLM、SGLang 或备用模型。

### 顺序驻留

```text
Qwen：按新源图批次生成场景目标与 SAM3 文本概念
→ 释放模型和显存
→ SAM3：逐图定向分割、候选后处理与资产生成
→ 释放模型和显存
→ Qwen：逐源图候选复核、语义与身份判断
→ 释放模型和显存
```

最新三段编排提供了完整服务器证据：Qwen首轮按4批调用4次并处理14张唯一图，23个目标全部进入SAM3；11张有候选的图片进入第二轮Qwen并调用11次。Qwen共加载2次、SAM3加载1次，两种模型均完成推理和释放，证明该环境可以顺序运行两个模型。该证据不代表当前首轮v5或M5-B语义效果已经通过；详细审计见 `PROGRESS.md`。

## 当前约束

- 数据盘低于30 GiB保守警戒线，不再下载备用模型；
- 业务入口必须继承项目 `HF_HOME` 与 `HF_HUB_CACHE`；
- 不根据容器可见的宿主机CPU和内存数量扩大并发；
- 对象卡片增长接近视觉上下文上限时，应显式分批并汇总，不能静默遗漏；
- 当前对象语义和实例身份问题属于业务效果，不是服务器环境故障。

环境搭建和检查命令见 `docs/03_服务器环境搭建指南.md`。
