# AutoDL 服务器环境分析

> 本文维护当前服务器环境、模型路径和部署约束。环境事实来自 `environment/server_env_report.json`；对象记忆实验与审计结论见 `PROGRESS.md`，当前协作方向见 `AGENTS.md`。

## 当前结论

现有 AutoDL 单卡环境已经证明能够顺序运行旧版 SAM3 与 Qwen3-VL。最新运行 `run_20260803T093048019080Z` 的顺序驻留峰值显存低于RTX 4090 24 GiB容量；该运行结构通过但语义覆盖只有15/24，失败边界来自首轮用词和SAM3召回，不是服务器环境故障。

当前 `data/memory/` 与 `environment/run_report.json` 保存上述最新运行的完整证据；报告实际使用首轮v4、第二轮v3、SAM3阈值0.4和原色候选上下文。当前代码已改为 SAM3 自动点网格、DINOv3 候选聚类、Qwen 聚类级审查，并让三个模型分阶段顺序驻留；现有服务器报告没有该流程的DINOv3、聚类效果或新显存证据，不能从旧峰值推断新流程已经可用。v0.17.4及更早的已删除实验可从Git提交 `f413654` 恢复。

Qwen 必须使用项目数据盘中的 Hugging Face 缓存，不能回退到系统默认缓存。模型权重、缓存和项目 Conda 环境均不进入 Git。

## 模型部署

### SAM3

- 使用官方图像 checkpoint；
- 使用 `16×16` 正点网格和实例交互接口自动提出类无关候选；
- 当前点提示质量阈值为0.88，不接收Qwen文本类别；
- 同一源图编码一次，再按32个点一批调用 `predict_inst`；
- 候选后处理在 CPU 可审计数据结构上完成；
- 不安装视频、训练或可选 CUDA 扩展。

### Qwen3-VL

- 使用 `Qwen/Qwen3-VL-8B-Instruct-FP8`；
- 从项目本地 snapshot 加载；
- 使用 Transformers 直接推理；
- 在DINOv3聚类后按最多8个聚类一批调用，承担完整物体/背景/零件判断、命名、文字身份假设和对象摘要；
- 不引入 vLLM、SGLang 或备用模型。

### DINOv3

- 当前代码固定 `facebook/dinov3-vitb16-pretrain-lvd1689m` 与 revision `5931719e67bbdb9737e363e781fb0c67687896bc`；
- 从项目本地目录加载，不在运行时联网补文件；
- 提取 CLS 与mask内patch视觉指纹；CLS用于本轮跨图候选聚类，全局+局部指纹用于历史对象匹配；
- 尚未获得服务器环境报告、真实聚类效果或新流程推理证据。

### 当前代码驻留方式

```text
加载SAM3 → 完成全部唯一新图自动候选 → 释放SAM3
→ 加载DINOv3 → 完成全部指纹与视觉聚类 → 释放DINOv3
→ 加载Qwen3-VL → 完成聚类批次审查 → 释放Qwen
→ 提交报告
```

最新正式实验只为旧三段编排提供证据：Qwen首轮按4批调用4次，11张有候选的图片进入第二轮并调用11次；Qwen共加载2次、SAM3加载1次。它不能证明当前自动点网格召回、DINOv3聚类、聚类级Qwen审查或类内身份效果。详细审计见 `PROGRESS.md`。

## 当前约束

- 数据盘低于30 GiB保守警戒线，不再下载备用模型；
- 业务入口必须继承项目 `HF_HOME` 与 `HF_HUB_CACHE`；
- 不根据容器可见的宿主机CPU和内存数量扩大并发；
- 对象摘要增长接近文本上下文上限时，应依据真实规模证据重新设计选择策略，当前不静默遗漏对象卡；
- 当前对象语义和实例身份问题属于业务效果，不是服务器环境故障。

环境搭建和检查命令见 `docs/03_服务器环境搭建指南.md`。
