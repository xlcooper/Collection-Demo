## 4. 模型决策

### 4.1 视觉侧：SAM3 图像 checkpoint

选择：`facebook/sam3` 官方 SAM3 图像权重。

理由：

- 第一阶段只处理图像，不需要 SAM 3.1 的多对象视频跟踪优化。
- 官方 `sam3.pt` 约 3.45 GB，功能边界更贴合当前阶段。
- 继续使用官方主仓库代码，后续如需升级 checkpoint，只改配置和适配器。

必须先验证一个关键假设：SAM3 官方接口以文本、点、框、mask 或示例提示为核心。项目所谓“全量发现物体”需要在固定样例上验证一种确定的提示策略；验证前不把它视为已解决能力。

官方资料：

- https://github.com/facebookresearch/sam3
- https://huggingface.co/facebook/sam3

### 4.2 MLLM：Qwen3-VL-8B-Instruct-FP8

首选：`Qwen/Qwen3-VL-8B-Instruct-FP8`。

理由：

- 8B 级模型比 4B 更适合细粒度类别识别、跨视角对象比较和严格结构化输出。
- 官方 FP8 权重约 10.6 GB，较 BF16 版本更适合 24 GiB 单卡，并为多图输入和 KV cache 留出空间。
- 官方模型卡提供 Transformers、vLLM 和 SGLang 路径。MVP 先使用 Transformers 直接推理，避免增加常驻服务。

回退：`Qwen/Qwen3-VL-4B-Instruct`。

只在以下任一情况出现时回退：

- FP8 在 RTX 4090/选定 PyTorch 组合上无法稳定加载；
- 单次多图对象比较仍发生显存不足；
- 磁盘扩容暂时无法完成。

暂不选择：

- 不以 8B BF16 作为 MVP 默认，避免挤压 24 GiB 显存和当前磁盘空间。
- 不使用 Thinking 版，当前任务需要低延迟、稳定 JSON，而非长推理链。
- 不同时维护 InternVL；只有 Qwen 路径验证失败时再做一次替代评估。

官方资料：

- https://github.com/QwenLM/Qwen3-VL
- https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct-FP8
- https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct

### 4.3 运行方式：顺序加载

MVP 不让两个模型同时驻留 GPU：

```text
阶段 A：加载 SAM3
  → 批量生成 proposal、mask、crop 和 overlay
  → 保存中间结果并释放 SAM3

阶段 B：加载 Qwen3-VL
  → 读取中间结果与对象记忆
  → 完成对象身份判断和结构化标注
  → 写入对象记忆库
```

这一方案牺牲少量流水线实时性，但显著减少显存风险，符合第一阶段批处理 MVP 的目标。
