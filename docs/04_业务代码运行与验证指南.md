# 业务代码运行与验证指南

本文说明当前 Demo 的稳定运行流程、输入输出、身份决定和服务器验证方式。真实实验结果只见根目录 `PROGRESS.md`；本文描述代码契约，不把尚未运行的新实现写成已验证能力。

## 1. 当前正式流程

正式入口：

```bash
python scripts/run_object_memory.py --input-dir <图片目录>
```

若仓库保留旧 `data/memory/`，必须同时使用 `--memory-root <新目录>`；程序不会改写旧 schema。

程序对每张唯一新图依次完成一个闭环：

```text
SHA-256 去重
→ Qwen 读取当前完整图片与所有已有对象文字摘要
→ 一次输出发现目标、SAM3 提示、当前可见事实、文字身份假设和拟议对象摘要
→ SAM3 按去重后的英文提示分割候选
→ 临时目标框与候选 bbox 一对一关联
→ DINOv3 生成 CLS 与 mask 内 patch 视觉指纹
→ 当前指纹与历史视角指纹比较
→ Qwen 假设与 DINOv3 证据共同形成 new / existing / uncertain
→ 提交 SQLite、指纹、展示资产和运行报告
```

三种模型在运行开始时联合加载，并保持驻留到本轮结束。每张唯一新图只允许一次 Qwen 调用；没有第二轮 Qwen、自动重试、拆单救援、备用模型或动态阈值。某一步失败时保存已有原始证据并明确失败。

## 2. Qwen 单次输出

Qwen 的输入只有：

- 当前视角完整原图；
- 当前记忆库中所有活跃对象的结构化文字摘要。

历史 crop、mask、视觉指纹和视觉分数不提供给 Qwen。每个目标必须输出：

| 字段 | 作用 |
|---|---|
| `target_id` | 当前图内的临时目标编号 |
| `object_name_zh` | 便于阅读的中文对象名 |
| `sam_text_prompt` | 唯一送入 SAM3 的小写英文完整物体类别 |
| `current_view_facts` | 当前视角确实可见的类别、类内特征、品牌/标记和部件外观 |
| `identity_hypothesis` | Qwen 基于图像和文字摘要给出的 `new / existing / uncertain` |
| `matched_object_id` | 仅 `existing` 可填写，且必须来自本次输入的对象摘要 |
| `identity_short_reason` | 可见证据的简短说明 |
| `proposed_object_summary` | 若最终提交，本对象应具有的完整累计摘要 |
| `temporary_target_anchor` | 归一化临时框，只用于与 SAM3 mask 关联 |

提示要求先判断物体大类，再主动观察类内区别，例如左右是否对称、轮廓比例、部件布局、纹理、磨损和清晰可读的品牌/型号。类别、颜色或材质相同不能单独证明是同一实例。颜色和材质必须附着到具体部件，不能写成多个同名的扁平“颜色”字段。

对象摘要只有一份，包括：基础类别、细分类别、稳定描述、类内区别特征、可见品牌/标记、部件级外观和摘要置信度。新视角若最终归入已有对象，Qwen 在本次单次调用中提出完整的更新后摘要；后续不再调用 Qwen 更新文字。

## 3. SAM3 与目标关联

同一张图只编码一次。相同 `sam_text_prompt` 即使对应多个同类实例，也只执行一次 SAM3 查询；SAM3 可以返回多个 mask。当前文字置信度保持 `0.4`，面积、重复、包含关系和每图候选上限继续使用确定性后处理。

同一英文提示下，程序计算 `temporary_target_anchor` 与 proposal bbox 的 IoU，并按 IoU 从高到低做一对一分配。默认最低 IoU 是 `0.1`。不能唯一对应 Qwen 目标的候选仍生成视觉指纹，但最终记为 `uncertain`，不会凭 SAM 文本自行建档。

每个保留候选生成：

- `crop.png`：mask 外为固定中性灰，只供本次指纹生成和页面展示；
- `mask.png`：全图尺寸黑白 mask，只供本次指纹生成和页面展示；
- `overlay.jpg`：原色场景定位图，只供审计；
- `fingerprint.npz`：后续自动身份比较使用的视觉指纹。

## 4. DINOv3 视觉指纹

默认使用固定本地快照：

```text
facebook/dinov3-vitb16-pretrain-lvd1689m
revision 5931719e67bbdb9737e363e781fb0c67687896bc
weights/dinov3/dinov3-vitb16-pretrain-lvd1689m
```

输入固定缩放为 `512 × 512`。每个 `.npz` 包含：

```text
global_embedding     float16 [D]     # L2 归一化 CLS
local_embeddings     float16 [N, D]  # mask 覆盖达标的 L2 归一化 patch
local_patch_indices  int32   [N, 2]  # patch 行列位置
```

实现按模型配置跳过 CLS 后的 register tokens，再读取完整 patch 网格，避免把 register token 误当局部视觉特征。

数据库同时保存指纹相对路径、SHA-256、模型 ID、revision、特征层、输入尺寸、dtype、维度和归一化状态。

每张当前图片开始比较前先固定历史指纹快照，同图内刚提交的候选不会成为后续候选的“历史”。匹配先用 CLS 余弦相似度对对象粗排，再对前 `local_top_k` 个对象的历史视角计算局部 patch 对应比例。每个对象取加权得分最高的历史视角：

```text
visual_score = global_weight × global_similarity
             + local_weight  × local_match_ratio
```

默认权重各为 `0.5`，临时匹配阈值为 `0.75`，第一与第二对象分差小于 `0.05` 时标为 `ambiguous`。这些值只是待实验参数，不代表已经完成同类实例标定。

指纹生成完成后，历史自动匹配只读取 `.npz`，不再读取历史 crop、mask 或原图。第一版不保存文本向量、不生成对象原型向量，也不使用向量数据库。

## 5. 最终身份决定

最终规则固定如下：

| Qwen 假设 | DINOv3 结果 | 最终决定 | 对象摘要 |
|---|---|---|---|
| `existing A` | 明确匹配 `A` | `existing A` | 提交 Qwen 拟议摘要 |
| `new` | 所有历史对象低于阈值 | `new` | 用拟议摘要新建对象 |
| `uncertain` | 任意 | `uncertain` | 不更新 |
| `existing A` | 匹配 `B`、无匹配或歧义 | `uncertain` | 不更新 |
| `new` | 明确匹配已有对象或歧义 | `uncertain` | 不更新 |
| 无法关联 Qwen 目标 | 任意 | `uncertain` | 不更新 |

`uncertain` 是正常终态，不触发第二次 Qwen 或重试。只有 `new` 和 `existing` 创建 observation 并更新对象摘要。

## 6. 记忆库结构

目录契约详见 [`data/README.md`](../data/README.md)。新工作流使用 SQLite schema v3：

- `objects`：每个物理对象一份当前结构化文字摘要；
- `observations`：对象、source、proposal 与指纹的引用和元数据；
- `proposals`：SAM 结果、目标关联、展示资产与指纹引用；
- `decisions`：Qwen 假设、DINOv3 视觉证据和最终决定；
- `raw_responses`：每图唯一一次 Qwen 原始回答；
- `run_reports`：本记忆库的正式运行报告。

crop 与 mask 不复制到 `objects/`。Web 对象卡通过 observation → proposal 引用展示它们；自动分析只使用保存的指纹。旧 schema v2 记忆库不自动迁移，在 Web 中只读展示。第一次运行新代码必须新建空白记忆库。

## 7. Web 实验台

Web 仍调用同一个正式入口，不复制模型流程：

```bash
python scripts/run_object_memory_web.py --host 127.0.0.1 --port 6006
```

页面展示：

1. 输入文件、SHA 去重、逐张删除和一键清空；清空输入不会删除记忆库中的源图副本或结果；
2. 每图 Qwen 目标、当前可见类内特征、文字身份假设和原始响应；
3. SAM3 查询、候选 crop/mask/overlay 与脚本过滤；
4. Qwen 身份假设、DINOv3 全局/局部/综合分数、歧义差距和最终决定；
5. 单一对象摘要、跨视角 crop/mask 时间线和候选血缘；
6. 三模型加载/推理耗时、指纹数量、运行错误和结构检查。

实验运行期间锁定输入和记忆库管理。旧 schema、失败、不完整或不可读的库只供复核；新实验从页面“新建空白库”开始。

## 8. 服务器运行与验证

```bash
cd /root/autodl-tmp/Collection-Demo
git pull --ff-only
conda activate "$PWD/.conda/envs/object-memory-demo"
export HF_HOME="$PWD/weights/qwen"
export HF_HUB_CACHE="$HF_HOME/hub"
```

依赖未变化时不要重复安装。先确认 DINOv3 本地快照：

```bash
test -f weights/dinov3/dinov3-vitb16-pretrain-lvd1689m/config.json
```

运行回归测试：

```bash
PYTHONPATH="$PWD/src" python -m unittest discover -s tests -v
```

回归测试通过后，首次服务器验证优先通过 Web 完成，这样可以直接查看逐阶段可视化。启动实验台：

```bash
export OBJECT_MEMORY_WEB_PASSWORD='<至少12字符的强密码>'
python scripts/run_object_memory_web.py --host 127.0.0.1 --port 6006
```

随后在 AutoDL 自定义服务地址打开页面，按以下顺序操作：

1. 确认输入区显示本次图片；
2. 点击“新建空白库”，不要选择历史 `data/memory/`；
3. 选中新库并启动完整实验；
4. 在中间结果中查看 Qwen、SAM3、DINOv3 和最终决定；
5. 在对象档案与候选血缘中审计摘要、crop、mask、视觉分数和对象归属。

Web 会在后台调用同一个 `scripts/run_object_memory.py` 正式入口，因此可视化运行与 CLI 运行不是两套算法。需要无页面复现或诊断时，才直接使用 CLI：

```bash
python scripts/run_object_memory.py \
  --input-dir data/input \
  --memory-root data/memory_dinov3_first \
  --validate-demo \
  --report environment/run_report_dinov3_first.json
```

这一步先验证三模型能否联合驻留、指纹是否完整落盘、每张唯一图是否只有一次 Qwen 调用，以及新 schema 是否端到端可读。当前固定输入没有同类不同实例，因此不能据此宣称类内实例辨识通过；后续需用用户采集的同类实例数据标定阈值和比较全局指纹与全局+局部指纹。

正式结果提交仍包含新记忆根和对应外部报告：

```bash
git add -A data environment
git commit -m "data: validate single-pass DINOv3 object memory"
git push
```

## 9. 报告字段

当前报告 schema 为 7。重点字段：

| 字段 | 含义 |
|---|---|
| `strategy` | 单次 Qwen、目标关联、视觉身份与不确定策略 |
| `models.qwen.calls` | 实际 Qwen 调用数，应等于成功处理的唯一新图数 |
| `models.dinov3` | 固定模型信息、指纹数、耗时、显存与分数范围 |
| `models.joint_peak_memory_mib` | 三模型联合驻留期间记录的 CUDA 峰值 |
| `visual_fingerprint_config` | 本轮完整指纹与匹配参数 |
| `scene_guidance.targets` | Qwen 的目标、当前事实、身份假设和拟议摘要 |
| `sam.prompt_detection_counts` | 实际执行的去重英文查询及候选数 |
| `decisions[].visual_evidence` | 最佳对象、历史观测、全局/局部/综合得分、分差和候选对象分数 |
| `decisions[].decision` | 最终 `new / existing / uncertain` |
| `decisions[].fingerprint` | 本候选指纹的路径和审计元数据 |

报告为 `passed` 只代表流程结构完整。物体是否找全、目标与 mask 是否正确关联、对象摘要是否真实、同类实例是否匹配正确，仍需结合图片和后续标注数据人工审计。

## 10. 常用参数

| 参数 | 作用 |
|---|---|
| `--input-dir` | 必填，递归读取图片 |
| `--config` | 配置文件，默认 `config/default.yaml` |
| `--memory-root` | 指定独立记忆根 |
| `--checkpoint` | 覆盖 SAM3 checkpoint |
| `--qwen-model` | 覆盖 Qwen 模型 ID |
| `--dinov3-model-path` | 覆盖 DINOv3 本地快照目录 |
| `--revision` | 指定 Qwen snapshot revision |
| `--allow-network` | 只允许 Qwen 联网解析；DINOv3 仍按本地路径加载 |
| `--validate-demo` | 对空白库增加 Demo 结构覆盖检查；增量续写不重复使用 |
| `--report` | 额外写出外部报告副本 |
| `--progress-file` | 即时追加 JSONL 进度事件 |

输入目录和记忆根不能相同，也不能互相包含。增量运行使用同一 schema v3 记忆根；相同 SHA 的已完成图片跳过，新图片会读取提交后的最新对象摘要和历史视觉指纹。
