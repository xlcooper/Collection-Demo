# 业务代码运行与验证指南

> **维护规则（强制）**：本文只维护业务代码运行方式和各开发里程碑的服务器验证命令；当前状态、下一动作和完成判断仍以 `PROGRESS.md` 为准。命令或入口变化后应直接替换失效内容，避免追加相互冲突的临时说明。

## 当前运行入口约定

当前第一阶段端到端实验总入口是 `python scripts/run_object_memory.py`，负责串联批量图片、SAM3、Qwen、SQLite 和运行报告。`scripts/verify_m*.py` 只用于复现里程碑或定位单个环节，不是正式总入口。

所有面向用户的新增入口统一采用 `python scripts/<脚本名>.py [参数]`。项目代码由 Git 同步；依赖安装只在首次配置或依赖文件变化时单独执行和说明，不作为每次运行的固定步骤。后续不再新增依赖项目安装才能调用的控制台快捷命令。已完成的 M1/M2 历史命令不为此返工。

## 7. M3 MLLM 流水线验证

M3 复用 `runs/m2` 中保留候选的 crop 和 overlay，不重新运行 SAM3，也不修改 SQLite。它先在空对象卡片列表下验证新对象标注，再把同一 crop 作为一张已知对象卡片的代表视图，验证 Qwen 能匹配回指定对象 ID。

### 7.1 M3 输入输出接口与 workflow

历史 M3 报告只代表当时接口。当前 `verify_m3.py` 已随主流程更新为源图级批量接口；它仍取一个 M2 候选做定向验证，但使用的输入和 JSON schema 与 M5 的“同图全部候选一次输入”完全相同：

```text
同一源图的全部 M2 保留候选
  ├─ proposal_id、候选来源
  ├─ 每个候选的 mask 隔离 crop：临时标注目标
  └─ 每个候选的 overlay：只用于理解边界和场景位置
→ 查询全部 active 对象卡片及每个对象最多2张最近参考图
→ 一次 Qwen 批量调用
  ├─ 第一步：逐候选独立判断 valid / ignored
  ├─ 第二步：为 valid 候选生成 temporary_annotation
  ├─ 第三步：把临时标注和候选图与全部卡片文字、参考图比较
  └─ 第四步：输出 new / existing / uncertain 及 final_annotation
→ 批量 JSON 校验
  ├─ 必须恰好覆盖本图每个 proposal_id 一次
  ├─ ignored 不得携带临时/最终标注
  ├─ valid 必须同时携带临时/最终标注
  └─ existing 的 object_id 必须来自本次提供的全部卡片
→ M3 只写验证报告，不写 SQLite
→ M4 接入记录动作
  ├─ new：用 final_annotation 创建对象、首次观测和决策记录
  ├─ existing：追加观测，并用 final_annotation 更新对象卡片
  ├─ ignored：记录候选终态和无效原因
  └─ uncertain：记录决策并进入 pending，不污染对象库
```

验证脚本运行两个独立场景：空记忆场景应输出 `new`，同一视图卡片场景应输出 `existing`。每个场景各调用一次批量接口，因此当前脚本真实总计2次 Qwen 推理，不是一个候选分两次调用。

本轮依赖没有变化，拉取代码后不需要再次安装项目：

若服务器上的 `runs/m2` 已被清理，先按第 4 节重新运行 `python scripts/verify_m2.py` 生成资产，再执行 M3。M3 原始响应写入 `runs/m3` 并随当前小规模 Demo 一起跟踪；机器可读报告写入：

## 10. M4 记忆闭环验证

M4 不再次调用 SAM3 或 Qwen，而是用确定性数据验证 M1–M3 之间的持久化接口。验证只使用临时记忆库，不会改动正式的 `data/memory`。

### 10.1 M4 写入接口与 workflow

```text
开始一次 run
→ 对源图 SHA-256 查询 SQLite
    ├─ 已 completed 或本批次已登记：返回 duplicate，整张图跳过
    └─ 未处理：登记 source 为 processing
→ 保存 M2 候选
    ├─ filtered：直接记录过滤原因，不调用 Qwen
    └─ 同一源图的全部保留候选：交给当前 Qwen 批量接口
→ 接收已经通过整批 schema 校验的逐候选最终决策
    ├─ new：创建一个 object，复制本次 crop/mask/overlay 为首次 observation
    ├─ existing：校验 matched_object_id 存在，追加 observation 并更新对象卡片标注
    ├─ ignored：记录 decision，proposal 进入 decided，不写 object/observation
    └─ uncertain：记录本次 attempt，proposal 保持 pending
→ pending 可使用同一个 proposal_id 和递增 attempt 再次提交判断
    ├─ 后续明确：按 new/existing/ignored 完成
    └─ 达到上层重试上限或处理异常：记录 failed
→ 每个候选的 proposal、decision、object、observation 在同一 SQLite 事务中写入
→ 图像资产先复制到 objects/<object_id>/observations/<observation_id>/；数据库失败时清理本次复制
→ 完成 source，汇总本 run 的图片、候选、四类决策、观测和活动对象计数
```

对象卡片查询返回全部 active 对象的结构化文字，并为每个对象附带配置数量的最近 crop 相对路径；当前 M5 将查询结果全部输入 Qwen，不做脚本相似度排序。M4 提供 pending/attempt/failed、new 建档以及 existing 更新对象卡片的持久化机制；实际批量调用和异常重试由 M5 总流程调度。

## 13. M5 第一阶段真实批量验收

M5 使用当前总入口 `python scripts/run_object_memory.py` 把前四个里程碑串起来。它处理整个图片目录，不需要用户逐张确认，也不接收 `cup`、`mug` 等外部类别提示：

```text
递归读取输入目录中的 jpg/jpeg/png/webp
→ 逐图计算 SHA-256 并查询 SQLite
    ├─ 已处理或本批次重复：跳过
    └─ 新图片：保存源图索引
→ 加载一次 SAM3，依次处理所有新图片
    ├─ 项目脚本在整张图上自动铺设点网格
    ├─ SAM3 根据每个点产生 mask，用户不提供类别词
    ├─ 低置信、过小/过大、重复、被完整候选包含的局部或超量候选作为 filtered 写入 SQLite
    └─ 保留候选生成 mask 隔离 crop、mask、overlay
→ 释放 SAM3 和显存
→ 加载一次 Qwen
→ 逐张源图处理 Qwen 批量输入
    ├─ 查询此时全部 active 对象卡片及每个对象最多2张最近参考图
    ├─ 整理本图全部保留候选的 mask 隔离 crop 和 overlay
    └─ 用一次 Qwen 调用同时输入全部候选、全部卡片文字和参考图
        ├─ 先判断每个候选是否为完整独立物体
        ├─ valid：先生成 temporary_annotation
        ├─ 再比较全部卡片和参考图，输出 new / existing / uncertain
        ├─ ignored：临时标注和最终标注都为空
        └─ valid：输出比较后更新的 final_annotation
→ 校验整批 JSON 完整覆盖本图候选且 existing ID 来自本次卡片
→ 按候选事务写入
    ├─ new：用 final_annotation 建档并保存首次观测
    ├─ existing：追加观测并更新已有对象卡片
    ├─ ignored：只记录无效原因
    └─ uncertain：记录 pending
→ 只有模型异常或整批 JSON 无法解析时才有限重试，默认最多2次；重试整张图
→ 释放 Qwen 和显存
→ 关闭 run，保存数据库摘要、逐图结果、模型耗时/显存和原始响应
```

对象卡片在每张源图调用前查询，因此较早源图刚建立或更新的档案可以参与后续源图归并；同一源图中的新对象要等本次批量输出写入后才进入数据库。当前小规模阶段不做相似度计算或 Top-K，Qwen 会遍历本次提供的全部 active 卡片和参考图。若未来上下文接近上限，应改为显式对象卡片分批与 Qwen 汇总，不能静默丢弃卡片。

这里的“无提示”是指用户和外部系统不提供物体类别。SAM3 官方仍是可提示分割模型，项目脚本会自动生成均匀采样点作为内部几何提示。它不是已经证明能穷举任意场景所有物体的官方模式，因此完整 M5 前先做 M5-A 候选校准，查看真实 crop/overlay 是否覆盖独立物体以及候选数量是否可接受。

### 13.1 准备验收图片

在服务器建立 `data/m5_input`，建议准备 10～20 张、每张以一个主要目标为主：

服务器 `data/` 下各类输入目录、实验记忆库及其内部文件的含义见 [`data/README.md`](../data/README.md)。目录存在只代表已经创建或运行过，不能代替验收报告。

- 具体物体 A 的 3～4 个角度；
- 与 A 同类别但确实不同的物体 B 的 3～4 个角度；
- 可选的另一类别物体 C 的 2～3 个角度；
- 至少一份完全相同文件的副本，用于验证 SHA-256 跳过；
- 至少一张无效、遮挡严重、背景占主导或多物体复杂场景图片。

“完全相同副本”必须直接复制文件；重新截图或重新压缩后哈希会变化。现在无需按类别准备 `--prompt`，图片可以包含不同类别；但 M5-A 校准时应人工确认主要独立物体是否都产生了合理候选。

当前本地验收集位于 Git 忽略的 `temp/`：图片已使用 `img_0001.jpg`～`img_0028.jpg` 的无语义编号，包含14张唯一图片和14张逐字节相同副本，涉及同一个水瓶、同一个鼠标和同一个饮料杯。`temp/ground_truth.md` 是隐藏真值，只用于报告回传后的人工复核，不能上传到模型输入目录。向服务器传输时只复制 `temp/img_*.jpg` 到 `data/m5_input`，不要重新编码图片。

该集合可以验证多视角归并、多个不同对象建档和 SHA-256 跳过；它没有同一细分类别的两个不同实例，也没有独立的纯无效场景。如果本轮核心链路通过，只能据此确认已覆盖的能力；需要声明同类不同实例分离或纯无效场景处理时，应另行补充相应图片，不能从当前数据推断。

### 13.3 M5-B：先验证 Qwen 接管
