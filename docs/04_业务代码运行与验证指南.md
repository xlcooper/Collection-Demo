# 业务代码运行与验证指南

本文说明当前 Demo 的稳定代码契约、运行方式和结果解释。面向读者的架构总览见 [README 架构图](../README.md#架构)；真实实验事实与验收结论只见根目录 `PROGRESS.md`，本文不把尚未验证的语义能力写成已通过。

## 1. 正式流程

正式入口：

```bash
python scripts/run_object_memory.py --input-dir <图片目录>
```

处理顺序固定为：

```text
输入 SHA-256 去重
→ SAM3 对全部唯一新图执行 16×16 正点网格自动分割
→ 脚本按分数、面积、IoU、包含关系和每图上限筛选候选
→ DINOv3 为全部保留候选生成 CLS 与 mask 内 patch 指纹
→ 用 CLS 相似度把不同源图中的候选组织为视觉聚类
→ 为每个聚类生成“隔离 crop + 原图定位”的代表视角接触表
→ 用聚类成员指纹与历史对象观测形成 DINOv3 匹配证据
→ Qwen 结合接触表、历史视觉证据和已有对象摘要完成聚类语义审查
→ Qwen 身份判断与历史视觉证据按固定规则对齐
→ 以聚类为事务写入对象、全部视角观测、决策和审计证据
```

模型按 `SAM3 → DINOv3 → Qwen` 顺序加载和释放，不联合驻留。没有 Qwen 生成 SAM 文本提示、逐候选 Qwen、第二轮 Qwen、自动重试、拆单救援或备用模型。失败会直接进入报告和对应记录。

## 2. SAM3 自动候选

SAM3 使用历史已验证过的实例交互接口 `predict_inst`。默认在每张图上建立 `16×16` 个正点提示，以32点为一批；每个点从多 mask 输出中保留得分最高的一个，因此每张图最多先形成256个原始候选。

确定性脚本随后依次处理：

1. 过滤低于 `0.88` 的点提示质量分；
2. 过滤空 mask、异常尺寸、过小或覆盖超过半图的 mask；
3. 按 mask IoU 去重；
4. 过滤被更高分完整 mask 高比例包含的候选；
5. 按分数保留每图最多24个候选。

这里的“去重”只删除同一图片内几何上重复或明显被包含的 mask，不删除跨视角观测。每个保留候选生成：

- `crop.png`：mask 外置为中性灰；
- `mask.png`：全图尺寸黑白 mask；
- `overlay.jpg`：原色场景定位图；
- 后续 DINOv3 生成的 `fingerprint.npz`。

crop 与 mask 用于生成当前候选指纹，crop 与 overlay 用于制作 Qwen 接触表，三者都可供页面审计；历史自动比较只读取指纹。

## 3. DINOv3 指纹与视觉聚类

默认模型：

```text
facebook/dinov3-vitb16-pretrain-lvd1689m
revision 5931719e67bbdb9737e363e781fb0c67687896bc
weights/dinov3/dinov3-vitb16-pretrain-lvd1689m
```

每个指纹包含：

```text
global_embedding     float16 [D]     # L2 归一化 CLS
local_embeddings     float16 [N, D]  # mask 内有效 patch
local_patch_indices  int32   [N, 2]  # patch 行列位置
```

本轮候选聚类只使用全局 CLS 余弦相似度，默认阈值 `0.75`。算法按高相似边优先合并，并遵守一条硬约束：同一个聚类不能包含来自同一 source 的两个候选。这样不会仅因同图中两个外观相近物体而把它们自动归为一个实例。

每个聚类记录成员候选、来源图片、代表视角、成员两两 CLS 相似度的最小值/均值/最大值。单成员聚类相似度记为 `1.0`，表示没有跨图一致性证据，并不表示已经确认实例身份。

默认最多选择4个代表视角。接触表每行左侧为 mask 隔离 crop，右侧为原图定位上下文；它既是 Qwen 输入，也是 Web 的最终解释资产。

## 4. Qwen 聚类级语义审查

Qwen 最多一次审查8个聚类。输入包括：

- 每个聚类的接触表与成员/相似度元数据；
- 聚类成员同历史对象比较得到的视觉证据；
- 当前记忆库全部活跃对象的结构化文字摘要。

Qwen 对每个聚类必须输出一个结果：

| `verdict` | 含义 | 是否写对象 |
|---|---|---|
| `object` | 聚类表现为一个完整、独立、值得记忆的物体 | 继续做身份决定 |
| `ignore` | 背景、支撑面、阴影、反射、固定结构、冗余碎片或已有完整物体的附属零件 | 否，成员候选记为过滤 |
| `uncertain` | 聚类混入不同物体、完整性不明或证据不足 | 否，成员候选保留不确定决定 |

接受为对象时，Qwen 同时输出 `new / existing` 身份假设和一份聚类级对象摘要。摘要包含类别、稳定描述、类内区别特征、清晰可读的品牌/标记、部件级颜色与材质以及置信度。不能从图中读出的品牌或型号不得猜测。

对象卡只保存一份当前汇总摘要，不保存每个视角各自的文字描述。已有对象的新聚类被接受后，本次聚类摘要直接替换为新的当前汇总；不会再调用一次 Qwen 做二次改写。

## 5. 历史对象匹配与最终决定

历史对象比较使用每个聚类成员的视觉指纹。先用 CLS 粗排，再对候选历史对象计算 mask 内局部 patch 对应比例：

```text
visual_score = 0.5 × global_similarity + 0.5 × local_match_ratio
```

默认匹配阈值为 `0.75`，第一和第二对象分差小于 `0.05` 时标为 `ambiguous`。聚类内不同成员若明确指向不同历史对象，整个聚类也标为歧义。以上参数只是实验起点，尚未完成同类不同实例标定。

最终规则：

| Qwen | 历史视觉证据 | 最终决定 |
|---|---|---|
| 完整对象 + `new` | `no_match` | `new` |
| 完整对象 + `existing A` | 明确匹配 `A` | `existing A` |
| `ignore` | 任意 | 过滤整个聚类 |
| Qwen `uncertain` | 任意 | `uncertain` |
| Qwen 与视觉证据冲突或视觉歧义 | 任意冲突 | `uncertain` |

一个 `new` 聚类最多创建一个对象。聚类第一个成员记录为 `new`，其余成员记录为指向该对象的 `existing`，并为每个成员各创建一条 observation。一个 `existing` 聚类的全部成员都写入同一已有对象。整组在一个 SQLite 事务中提交。

## 6. 记忆库结构

完整目录见 [`data/README.md`](../data/README.md)。当前 SQLite schema 仍为 v3，新增的聚类级解释保存在运行报告、原始响应和 `clusters/` 资产中：

- `objects`：每个长期对象一份当前结构化摘要；
- `observations`：对象、source、proposal 和视觉指纹的引用；
- `proposals`：SAM3 自动候选、展示资产、聚类 ID 和指纹；
- `decisions`：Qwen 聚类身份假设、历史 DINOv3 证据和最终决定；
- `clusters/`：代表视角接触表；
- `raw_responses/`：每个聚类批次的完整 Qwen 输入记录与原始回答；
- `run_reports/`：每次正式运行的报告。

数据库与资产目录必须整体移动、提交或删除。旧 schema v2 库不自动迁移，只读展示。

## 7. Web 实验台与结果解释

Web 仍通过独立子进程调用同一正式入口：

```bash
python scripts/run_object_memory_web.py --host 127.0.0.1 --port 6006
```

页面按四个中间阶段解释结果：

1. 输入整理：输入文件、内容指纹、唯一 source 与重复文件；
2. 自动分割：每张图作为一个默认折叠的结果块，摘要显示点网格原始、SAM脚本保留和脚本过滤数量；展开后查看全部SAM保留候选及crop/mask/overlay。这里是阶段快照，不按后续Qwen结果隐藏候选，也不显示“已判断/已忽略”等后续标签；
3. 视觉聚类：页面摘要集中解释聚类约束、`clu_…`聚类编号、`prop_…`候选编号和CLS最低/平均/最高相似度；各卡片只展示本聚类证据，不重复原理说明；
4. 语义审查：历史对象匹配分数、Qwen 完整性/身份判断、最终决定和对象 ID。

最终区保留对象卡、观测时间线与候选血缘。候选血缘中的 `target_id` 在新流程里是聚类 ID，`prompt` 固定为 `automatic_point_grid`，不是 Qwen 文本提示。

Web 已按 `input_path` 与 `source_id` 建立别名合并，因此5个上传文件不会因为进度事件和正式报告使用不同键而显示成10行。

Web运行不自动启用固定Demo内容门槛，只按流程和数据结构判断运行是否成功。历史报告若同时出现 `status=failed`、`pipeline_status=passed`，且唯一未满足项是固定Demo覆盖条件，页面会明确显示“流程通过、旧覆盖条件未满足”。原始报告保持不变。

## 8. 服务器运行与验证

```bash
cd /root/autodl-tmp/Collection-Demo
git pull --ff-only
conda activate "$PWD/.conda/envs/object-memory-demo"
export HF_HOME="$PWD/weights/qwen"
export HF_HUB_CACHE="$HF_HOME/hub"
test -f weights/dinov3/dinov3-vitb16-pretrain-lvd1689m/config.json
PYTHONPATH="$PWD/src" python -m unittest discover -s tests -v
```

测试通过后优先从 Web 新建空白记忆库运行固定输入。重点人工复核：

1. SAM3 点网格是否覆盖所有真实物体，是否仍有大量背景/零件候选；
2. 脚本过滤是否误删小物体或把完整物体当包含候选删除；
3. DINOv3 是否把同一物体的跨视角候选聚在一起，是否误合并同类实例；
4. Qwen 是否正确区分完整对象、背景和零件；
5. 每个对象的观测数、类内特征和最终归属是否与图片一致；
6. 三个模型是否确实顺序释放，显存峰值和总耗时是否可接受。

当前固定输入没有系统覆盖同类不同实例，不能据此宣称类内实例辨识通过。后续需要用户采集的数据标定聚类阈值和历史匹配阈值。

CLI 无页面复现：

```bash
python scripts/run_object_memory.py \
  --input-dir data/input \
  --memory-root data/memory_cluster_first \
  --validate-demo \
  --report environment/run_report_cluster_first.json
```

## 9. 报告字段

当前报告 schema 为8。重点字段：

| 字段 | 含义 |
|---|---|
| `strategy` | 自动候选、聚类、Qwen 批次和顺序驻留策略 |
| `models.sam3.raw_candidates` | 全部点网格原始候选数 |
| `models.dinov3.fingerprints / clusters` | 指纹数与视觉聚类数 |
| `models.qwen.calls` | 聚类批次数，不再等于图片数 |
| `models.execution_peak_memory_mib` | 三个顺序阶段中最大的单阶段 CUDA 峰值 |
| `images[].sam` | 每图原始、保留、过滤候选和过滤原因 |
| `images[].dinov3.cluster_ids` | 当前图候选进入的聚类 |
| `clusters[]` | 成员、代表视角、接触表、相似度、历史证据、Qwen 判断与最终对象 |
| `cluster_counts` | `new / existing / ignored / uncertain / failed` 聚类数 |
| `images[].decisions[]` | 每个候选最终决定、对象 ID、视觉证据和指纹 |

报告为 `passed` 只代表流程结构完整。物体是否找全、聚类是否正确、Qwen 是否正确过滤、同类实例是否匹配正确，仍需结合接触表、原图和后续标注数据人工审计。

## 10. 常用参数

| 参数 | 作用 |
|---|---|
| `--input-dir` | 必填，递归读取图片 |
| `--config` | 配置文件，默认 `config/default.yaml` |
| `--memory-root` | 指定独立记忆根 |
| `--checkpoint` | 覆盖 SAM3 checkpoint |
| `--qwen-model` | 覆盖 Qwen 模型 ID |
| `--dinov3-model-path` | 覆盖 DINOv3 本地快照目录 |
| `--revision` | 指定 Qwen snapshot revision |
| `--allow-network` | 只允许 Qwen 联网解析；DINOv3 仍从本地路径加载 |
| `--validate-demo` | 仅在CLI明确复现约定的固定Demo输入时增加内容覆盖检查；Web不自动启用 |
| `--report` | 额外写出外部报告副本 |
| `--progress-file` | 即时追加 JSONL 进度事件 |

输入目录和记忆根不能相同，也不能互相包含。增量运行使用同一 schema v3 记忆根；相同 SHA 的已完成图片跳过，新图片在聚类审查时读取当前对象摘要和历史视觉指纹。
