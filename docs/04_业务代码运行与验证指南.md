# 业务代码运行与验证指南

本文只说明当前 Demo 怎么运行、每一步产生什么，以及服务器如何回传结果。真实实验结果见根目录 `PROGRESS.md`。

## 1. 正式入口

### 1.1 命令行入口

```bash
python scripts/run_object_memory.py --input-dir <图片目录>
```

当前业务流程是：

```text
图片哈希去重
→ Qwen第一次看原图，列出值得深入观察的完整物体
→ SAM3按简短类别名寻找并分割物体
→ 脚本筛选候选，保存crop、mask和原色定位图
→ Qwen第二次判断候选有效性、物体语义和具体实例身份
→ 写入SQLite、对象观测和运行报告
```

首轮 Qwen 默认每批最多看4张新图。每个目标包含：

- `target_id`：该图中第几个目标；
- `object_name_zh`：完整物体的中文名称；
- `sam_text_prompt`：Qwen 计划用于 SAM3 的英文查找词，执行时会原样传入；`sam.prompt_detection_counts` 只证明该图中已完成并记录检测数的查询，中途失败时未记录条目的发送状态不作推断。

`sam_text_prompt` 先确定 `computer mouse`、`water bottle`、`drink cup` 这类稳定基础类别，再按需保留至多一个清晰且有助检索的前置修饰词，例如 `transparent water bottle`。v5 提示不生成 `with/and` 特征尾句；解析器仅为避免历史整批失败而继续宽容旧的单物体表达。`or` 形式的备选提示仍不接受。中文名称与英文基础类别的一致性由 Qwen 在输出前自检，页面会并列展示供人工复核；当前没有用固定中英词表冒充视觉语义校验。

SAM3 对同一张图只编码一次，每条文字提示执行一次查找。当前文字置信度阈值为0.4；降低阈值可能提高遮挡视角召回，也可能增加误检和第二轮 Qwen 成本。脚本继续检查面积、重复、同提示包含关系和每图候选上限。

第二轮 Qwen 把 mask 隔离的 crop 作为颜色、材质和纹理依据；场景图保留原始颜色，只画候选定位框，用于判断边界、遮挡和附着关系。提示规则要求仍附着在完整物体上的盖子、吸管、把手等不得单独建档。当前视角描述写入 observation，稳定累计信息写入对象卡。

### 1.2 Web 实验台入口

Web 页面调用同一个 `scripts/run_object_memory.py` 正式入口，不复制或改写模型流程：

```bash
python scripts/run_object_memory_web.py \
  --host 127.0.0.1 \
  --port 6006
```

页面提供四个主视图：

1. **实验输入**：显示文件数、唯一内容数、重复副本、缩略图、尺寸和 SHA；支持安全上传与删除。运行期间输入被锁定。
2. **逐阶段中间结果**：按真实落盘事件展示 SHA 去重、首轮 Qwen 目标、SAM3 每条提示的检测数与候选资产、第二轮 Qwen 的有效性和对象决定。
3. **SQLite 对象记忆**：对象卡展示稳定累计属性，观测时间线展示跨视角 crop；候选血缘表连接 source、proposal、decision、observation 和 object。
4. **结果摘要**：汇总输入、目标、0候选提示、阈值上候选、过滤、四类决定、对象、观测、模型耗时、总墙钟时间和错误；流程与数据检查状态和人工语义验收分开显示。

Web 服务只允许一个活跃实验，运行时以当前 Python 解释器启动独立子进程并继承 `HF_HOME`、`HF_HUB_CACHE`。进度采用固定阶段边界和已完成工作单元计算；模型加载期间保持阶段运行状态，不按时间线性伪造百分比。不提供取消、自动重试或任意命令入口；记忆清理只通过带确认的受控整库删除/默认库清空完成。

如果子进程在正式报告生成前因导入错误、OOM或信号异常退出，页面会显示退出码和固定 `process.log` 的有界尾部；完整日志仍保留在对应的 `temp/web_runs/<web_run_id>/`，不会把任意服务器文件开放给浏览器。

监听非回环地址时必须设置 Basic 密码：

```bash
export OBJECT_MEMORY_WEB_PASSWORD='<设置一个至少12字符的强密码>'

python scripts/run_object_memory_web.py \
  --host 0.0.0.0 \
  --port 6006
```

## 2. 当前输入与输出

```text
data/input/                 固定输入，28个文件
data/memory/                默认输出；当前不存在，下一次运行自动创建
data/memory_<内部编号>/      Web 新建的独立完整记忆库，可同时保留多份
environment/run_report.json 外部运行报告
temp/web_runs/              Web进程状态、进度JSONL与日志；本地忽略
```

默认记忆根为空，所以这次重跑不需要 `--memory-root`。程序会创建：

```text
data/memory/
├─ memory.sqlite
├─ sources/
├─ proposals/
├─ objects/
├─ raw_responses/
└─ run_reports/
```

每个正式候选目录有：

- `crop.png`：只保留 mask 内的原始物体像素；
- `mask.png`：黑白分割区域；
- `overlay.jpg`：保留原图颜色并画出候选位置框。

## 3. 服务器执行顺序

先同步本地已经完成的删除和优化：

```bash
cd /root/autodl-tmp/Collection-Demo
git pull --ff-only
conda activate "$PWD/.conda/envs/object-memory-demo"
```

只有 `requirements.txt` 发生变化时才执行依赖更新；首次引入 Web 实验台的服务器需要执行一次：

```bash
python -m pip install -r requirements.txt
```

设置 Qwen 数据盘缓存：

```bash
export HF_HOME="$PWD/weights/qwen"
export HF_HUB_CACHE="$HF_HOME/hub"
```

先运行回归测试：

```bash
PYTHONPATH="$PWD/src" python -m unittest discover -s tests -v
```

测试通过后运行全新实验：

```bash
python scripts/run_object_memory.py \
  --input-dir data/input \
  --validate-demo \
  --report environment/run_report.json
```

也可以在同一环境中启动 Web 实验台，再从页面点击“运行完整实验”。SSH 隧道访问使用回环监听：

```bash
python scripts/run_object_memory_web.py --host 127.0.0.1 --port 6006
```

AutoDL 自定义服务访问使用非回环监听和强密码：

```bash
export OBJECT_MEMORY_WEB_PASSWORD='<设置一个至少12字符的强密码>'
python scripts/run_object_memory_web.py --host 0.0.0.0 --port 6006
```

页面运行前必须先确认“本次实验使用的对象记忆库”：

- `新建空白库` 会生成独立内部编号，适合全新实验和并排比较；
- 选择 `可继续写入` 的已有库，会读取其中对象卡并把本次新观测追加回同一个库；
- Web 只对没有历史 run 的空白库启用全新 Demo 覆盖检查；续写已有库仍执行正式流程与基础报告检查，但不会重复要求本轮必须同时产生“新对象、已有对象匹配和重复图”这组首轮验收条件；
- 明确选择会由服务端记录，刷新页面或重启 Web 服务后仍恢复到上次所选库；
- 失败、不完整或不可读的库显示为 `仅供复核` 或 `读取失败`，不能继续写入，但可查看或整库删除；
- 运行期间输入、记忆库选择、新建和删除全部锁定。浏览器只提交内部编号，不能提交服务器路径。

实验完成后提交结果：

```bash
git add -A data environment/run_report.json
git commit -m "data: add fresh object-memory experiment"
git push
```

不需要额外执行 `echo $?` 或 JSON 格式化命令。推送后通知本地审计即可。

## 4. 如何查看记忆效果

先看三类内容：

1. `environment/run_report.json`：整次实验处理了多少图、目标、SAM3候选、决定和观测；
2. 页面所选记忆库的 `objects/`：每个 `object_id` 下实际保存了哪些视角；
3. 页面所选记忆库的 `memory.sqlite`：对象、观测、候选和决定之间的完整关系。

报告 schema 版本为6。重点字段：

| 字段 | 大白话含义 |
|---|---|
| `models.sam3.confidence_threshold` | 本次SAM3实际使用的文字阈值 |
| `scene_guidance` | 第一次 Qwen 在这张图里提出了什么目标；中文物体名和理由用于阅读与审计 |
| `scene_guidance.targets[].sam_text_prompt` | 计划用于 SAM3 的英文查询原文；执行时不会改写，其他中文字段不用于 SAM3 查询 |
| `sam.prompt_detection_counts` | 已完成并记录检测数的每条英文查询返回几个区域；键就是查询原文，中途失败时不代表未记录条目一定没有发送 |
| `sam.zero_candidate_prompts` | 哪些提示没有找到任何区域 |
| `sam.above_confidence_threshold_candidates` | 高于0.4阈值的临时候选数 |
| `sam.kept` / `sam.filtered` | 脚本保留和删除了多少候选 |
| `decisions` | 第二次 Qwen 对每个正式候选做了什么决定 |

第二轮的完整 `temporary_annotation` 和 `final_annotation` 保存在报告与原始响应中；SQLite 的 observation 当前单独保存当次临时描述，其他累计结构化属性保存在对象卡中。

报告显示 `passed` 只代表程序设定的结构检查通过；对象是否真的正确，仍要逐图核对候选和对象档案。

Web 页面的“SQLite 对象记忆”把上述三类内容组合为两种互补视角：

- **对象卡—观测时间线**：适合检查一个长期对象的稳定描述、颜色、材质以及跨图片观测是否正确归并；
- **候选血缘**：适合从某张源图反查 SAM3 文本提示、候选分数、过滤/决定、匹配对象和资产。

页面只执行固定只读查询并按白名单提供图片资产，不开放任意 SQL，也不把整个 memory 根作为静态目录暴露。

## 5. 常用参数

| 参数 | 作用 |
|---|---|
| `--input-dir` | 必填，递归读取图片 |
| `--config` | 配置文件，默认 `config/default.yaml` |
| `--memory-root` | 改用另一个记忆根；默认是 `data/memory` |
| `--checkpoint` | 覆盖 SAM3 checkpoint 路径 |
| `--qwen-model` | 覆盖 Qwen 模型 ID |
| `--revision` | 指定 Qwen snapshot revision |
| `--allow-network` | 允许联网解析或下载 Qwen 模型 |
| `--validate-demo` | 为全新空白库增加首轮 Demo 结构覆盖检查；增量续写不要重复使用 |
| `--report` | 额外写出一份外部运行报告 |
| `--progress-file` | 可选的新 JSONL 文件；逐条立即写入结构化进度事件，供 Web 或其他监视器读取 |

输入目录和记忆根不能相同，也不能互相包含。

## 6. 增量运行与独立实验

当一个记忆根中的相关图片都已成功完成时，再把新图片放入输入目录并使用同一记忆根：相同哈希会跳过，新图片会和已有对象卡及参考图比较。

Web 中直接选择状态为“可继续写入”的已有库即可完成同一操作；Web 会自动识别这是增量续写，不再套用只适合全新空白库的 `--validate-demo` 覆盖门槛。若要隔离结果，先点击“新建空白库”。删除操作会整库移除 SQLite、源图副本、候选、对象观测、原始回答和内部报告，输入图片不受影响；服务端会先隔离目标库并提交选择与运行状态，任一步写盘失败都会恢复原库，极少数最终清理失败会由页面明确提示仍有临时隔离副本。

需要并排比较时，改用一个不存在的新目录：

```bash
python scripts/run_object_memory.py \
  --input-dir data/input \
  --memory-root data/memory_compare \
  --report environment/run_report_compare.json
```

记忆根是一个整体。清理失败实验时必须一起处理 SQLite、图片、原始回答和内部报告，不能只删除其中一部分。
