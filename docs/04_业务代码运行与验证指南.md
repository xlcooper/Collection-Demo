# 业务代码运行与验证指南

本文只说明当前 Demo 怎么运行、每一步产生什么，以及服务器如何回传结果。真实实验结果见根目录 `PROGRESS.md`。

## 1. 正式入口

```bash
python scripts/run_object_memory.py --input-dir <图片目录>
```

当前业务流程是：

```text
图片哈希去重
→ Qwen第一次看原图，列出值得深入观察的完整物体
→ SAM3按简短类别名寻找并分割物体
→ 脚本筛选候选，保存crop、mask和原色定位图
→ Qwen第二次判断候选有效性、物体语义和具体实例身份
→ 写入SQLite、对象观测和运行报告
```

首轮 Qwen 默认每批最多看4张新图。每个目标包含：

- `target_id`：该图中第几个目标；
- `object_name_zh`：完整物体的中文名称；
- `sam_text_prompt`：交给 SAM3 的英文查找词。

`sam_text_prompt` 优先使用 `computer mouse`、`water bottle`、`drink cup` 这类最短稳定类别。提示要求 `and` 只描述同一物体的多个特征，不能连接两个独立物体；程序不再仅凭出现 `and` 就让整批失败。`or` 形式的备选提示仍不接受。

SAM3 对同一张图只编码一次，每条文字提示执行一次查找。当前文字置信度阈值为0.4；降低阈值可能提高遮挡视角召回，也可能增加误检和第二轮 Qwen 成本。脚本继续检查面积、重复、同提示包含关系和每图候选上限。

第二轮 Qwen 把 mask 隔离的 crop 作为颜色、材质和纹理依据；场景图保留原始颜色，只画候选定位框，用于判断边界、遮挡和附着关系。提示规则要求仍附着在完整物体上的盖子、吸管、把手等不得单独建档。当前视角描述写入 observation，稳定累计信息写入对象卡。

## 2. 当前输入与输出

```text
data/input/                 固定输入，28个文件
data/memory/                默认输出；当前不存在，下一次运行自动创建
environment/run_report.json 外部运行报告
```

默认记忆根为空，所以这次重跑不需要 `--memory-root`。程序会创建：

```text
data/memory/
├─ memory.sqlite
├─ sources/
├─ proposals/
├─ objects/
├─ raw_responses/
└─ run_reports/
```

每个正式候选目录有：

- `crop.png`：只保留 mask 内的原始物体像素；
- `mask.png`：黑白分割区域；
- `overlay.jpg`：保留原图颜色并画出候选位置框。

## 3. 服务器执行顺序

先同步本地已经完成的删除和优化：

```bash
cd /root/autodl-tmp/Collection-Demo
git pull --ff-only
conda activate "$PWD/.conda/envs/object-memory-demo"
```

设置 Qwen 数据盘缓存：

```bash
export HF_HOME="$PWD/weights/qwen"
export HF_HUB_CACHE="$HF_HOME/hub"
```

先运行回归测试：

```bash
PYTHONPATH="$PWD/src" python -m unittest discover -s tests -v
```

测试通过后运行全新实验：

```bash
python scripts/run_object_memory.py \
  --input-dir data/input \
  --validate-demo \
  --report environment/run_report.json
```

实验完成后提交结果：

```bash
git add data/memory environment/run_report.json
git commit -m "data: add fresh object-memory experiment"
git push
```

不需要额外执行 `echo $?` 或 JSON 格式化命令。推送后通知本地审计即可。

## 4. 如何查看记忆效果

先看三类内容：

1. `environment/run_report.json`：整次实验处理了多少图、目标、SAM3候选、决定和观测；
2. `data/memory/objects/`：每个 `object_id` 下实际保存了哪些视角；
3. `data/memory/memory.sqlite`：对象、观测、候选和决定之间的完整关系。

报告 schema 版本为6。重点字段：

| 字段 | 大白话含义 |
|---|---|
| `models.sam3.confidence_threshold` | 本次SAM3实际使用的文字阈值 |
| `scene_guidance` | 第一次 Qwen 在这张图里提出了什么目标 |
| `sam.prompt_detection_counts` | 每条文字提示让 SAM3 找到几个区域 |
| `sam.zero_candidate_prompts` | 哪些提示没有找到任何区域 |
| `sam.above_confidence_threshold_candidates` | 高于0.4阈值的临时候选数 |
| `sam.kept` / `sam.filtered` | 脚本保留和删除了多少候选 |
| `decisions` | 第二次 Qwen 对每个正式候选做了什么决定 |

第二轮的完整 `temporary_annotation` 和 `final_annotation` 保存在报告与原始响应中；SQLite 的 observation 当前单独保存当次临时描述，其他累计结构化属性保存在对象卡中。

报告显示 `passed` 只代表程序设定的结构检查通过；对象是否真的正确，仍要逐图核对候选和对象档案。

## 5. 常用参数

| 参数 | 作用 |
|---|---|
| `--input-dir` | 必填，递归读取图片 |
| `--config` | 配置文件，默认 `config/default.yaml` |
| `--memory-root` | 改用另一个记忆根；默认是 `data/memory` |
| `--checkpoint` | 覆盖 SAM3 checkpoint 路径 |
| `--qwen-model` | 覆盖 Qwen 模型 ID |
| `--revision` | 指定 Qwen snapshot revision |
| `--allow-network` | 允许联网解析或下载 Qwen 模型 |
| `--validate-demo` | 增加 Demo 结构覆盖检查 |
| `--report` | 额外写出一份外部运行报告 |

输入目录和记忆根不能相同，也不能互相包含。

## 6. 增量运行与独立实验

当一个记忆根中的相关图片都已成功完成时，再把新图片放入输入目录并使用同一记忆根：相同哈希会跳过，新图片会和已有对象卡及参考图比较。

需要并排比较时，改用一个不存在的新目录：

```bash
python scripts/run_object_memory.py \
  --input-dir data/input \
  --memory-root data/memory_compare \
  --report environment/run_report_compare.json
```

记忆根是一个整体。清理失败实验时必须一起处理 SQLite、图片、原始回答和内部报告，不能只删除其中一部分。
