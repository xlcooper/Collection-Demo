# 业务代码运行与验证指南

本文只维护当前 Demo 的正式运行入口、输入输出契约和验证方式。实验执行事实与审计结论以根目录 `PROGRESS.md` 为准。

## 1. 正式入口

```bash
python scripts/run_object_memory.py --input-dir <图片目录>
```

该入口串联：

```text
图片发现与哈希幂等
→ Qwen 首轮场景观察（默认每批4张新图）
→ SAM3 文本概念定向分割
→ 候选过滤和图像资产
→ Qwen 第二轮源图级候选与记忆判断
→ SQLite 对象记忆
→ 运行报告
```

首轮只决定哪些独立物体值得机械臂进一步观察，并为 SAM3 生成英文小写物体概念，不写入候选 decision。概念最长64字符，单词数不设固定上限，但必须只描述一个具体物体；`with` 可以描述同一完整物体的可见特征，例如 `water bottle with handle`，不能连接两个独立物体。当前代码还会直接拒绝包含 `and` 或 `or` 的短语；最新实验已证明这会误伤单个物体的属性描述，属于待修正问题。每个配置批次只调用一次 Qwen；模型、格式或协议失败会保存原始结果并直接让该批 source 失败，不自动重试、拆单救援、静默规范化、降级或回退。

SAM3 对规范 source 资产只编码一次，再逐概念返回所有匹配实例。其输出已经过 processor 文本置信度阈值，然后由项目脚本执行面积、高 IoU、同概念包含关系和候选上限过滤。候选上限先为每个有检测的概念保留最高分 mask，再按全局分数补足。

第二轮继续使用现有的有效性、结构化标注、`new/existing/ignored/uncertain` 和对象卡片比较逻辑。首轮概念只是检索假设，并且在 crop 和 overlay 之后才作为来源信息展示；第二轮必须先根据可见像素独立复核，并且每张源图同样只调用一次 Qwen，失败直接记录。

历史分阶段验证脚本已从最终 Demo 结构中删除。

## 2. 当前固定输入与默认输出位置

```text
data/input/             固定输入集
data/memory/            v0.16.1 失败实验；也是配置中的默认记忆根
data/memory_v017_01/    v0.17.0 失败实验；独立比较记忆根
data/memory_v017_02/    v0.17.4 失败实验；独立比较记忆根
```

当前三个记忆根都含已结束但存在 failed source 的正式 run，应分别作为整体审计证据保留。存储层只允许未完成哈希在原 run 内恢复，新 run 不能直接接管；因此当前不能省略 `--memory-root`，也不能复用任何一个已保留记忆根直接重做。

对于全部 source 已完成的记忆根，后续增量执行时：

- 相同哈希的已完成图片会直接跳过；
- 新图片会写入现有对象记忆；
- 已有对象卡片和参考图会参与新图片的身份比较。

重做、修复后复验或并排比较必须使用独立空记忆根。

## 3. 增量运行（仅适用于可继续的记忆根）

只有目标记忆根不存在，或其中相关 source 已全部完成时，才使用该方式。当前保留的默认 `data/memory/` 不满足这一条件。

```bash
cd /root/autodl-tmp/Collection-Demo
conda activate "$PWD/.conda/envs/object-memory-demo"

export HF_HOME="$PWD/weights/qwen"
export HF_HUB_CACHE="$HF_HOME/hub"

python scripts/run_object_memory.py \
  --input-dir data/input \
  --report environment/run_report.json
```

没有传入 `--memory-root` 时，程序使用 `config/default.yaml` 中的 `data/memory`。执行前必须确认该根适合增量运行。

## 4. 在独立空记忆中运行

为重做或并排实验选择一个不存在的新目录：

```bash
python scripts/run_object_memory.py \
  --input-dir data/input \
  --memory-root data/memory_next \
  --validate-demo \
  --report environment/run_report_next.json
```

`--validate-demo` 只检查运行路径覆盖：

- 至少2个 `new`；
- 至少1个 `existing`；
- 至少1张完全重复图片被跳过；
- 最终没有 pending 或 failed proposal。

报告会另外记录本轮是否实际出现 filtered/ignored 候选，但这只是分支观察，不是通过条件；干净输入不需要为了验收人为产生坏候选。这些结构条件不能判断对象身份是否正确，也不能代替输入真值和逐图对象 ID 复核。

## 5. 常用参数

| 参数 | 作用 |
|---|---|
| `--input-dir` | 必填，递归读取支持的图片 |
| `--config` | 配置文件，默认 `config/default.yaml` |
| `--memory-root` | 覆盖配置中的记忆根目录 |
| `--checkpoint` | 覆盖 SAM3 checkpoint 路径 |
| `--qwen-model` | 覆盖 Qwen 模型 ID |
| `--revision` | 指定 Qwen snapshot revision |
| `--allow-network` | 允许 Qwen 从网络解析或下载模型 |
| `--validate-demo` | 增加结构路径覆盖检查 |
| `--report` | 将运行报告额外写入指定路径 |

输入目录和记忆根目录不能相同，也不能互相包含。

## 6. 输出结构

每个记忆根都是一个不可拆分的完整单元：

```text
<memory_root>/
├─ memory.sqlite
├─ sources/
├─ proposals/
├─ objects/
├─ raw_responses/
└─ run_reports/
```

SQLite 与文件资产通过相对路径关联。清理或替换结果时必须处理整个记忆根，不能只删除数据库或单类图像。

外部 `--report` 是内部 `run_reports/` 报告的第二份副本，便于从仓库根目录快速检查。

首轮每个批次保存一份 `response.json`，第二轮每个 source 保存一份 `response.json`。报告直接关联这份响应及其错误；原始响应写盘失败会阻止对应结果继续进入下一环节。

## 7. 结果检查

一次运行至少检查：

1. 顶层运行状态、模型加载顺序和 external errors；
2. 重复图片是否在两轮 Qwen 和 SAM3 之前被跳过；
3. 首轮是否精确覆盖每个新 `source_id`，并分别核对 Qwen 原始目标、schema 接受目标和实际进入 SAM3 的目标，避免把结构记账误当成功分析；
4. 每个 proposal 是否能通过 `source_id + sam_text_prompt` 回溯到首轮唯一目标和原始响应；
5. source、proposal、decision、object、observation 计数是否与 SQLite 一致；
6. 所有 source/crop/mask/overlay/raw-response 路径是否存在；
7. `new` 与 `existing` 是否依据真值指向正确具体实例；
8. accepted observations 是否包含背景、固定装置、阴影或无意义局部；
9. 两轮 Qwen 各自的调用数、token、耗时和峰值显存，以及单元测试摘要是否可核对。

报告的 `status=passed` 只代表程序设定的结构条件通过，不自动代表对象记忆效果通过。

## 8. 当前回归测试

```bash
cd /root/autodl-tmp/Collection-Demo
conda activate "$PWD/.conda/envs/object-memory-demo"
PYTHONPATH="$PWD/src" python -m unittest discover -s tests -v
```

终端提示符仍显示 `(base)` 时不要运行测试；那会使用系统 Python，无法证明项目代码是否通过。`PYTHONPATH` 只让测试进程读取仓库中的 `src/object_memory`，不安装或修改项目环境。

测试目录按当前功能组织，覆盖配置与存储、`with` 文本契约、首轮场景协议、SAM3 文本候选、按概念公平限额、候选后处理、批量身份判断、记忆事务、Demo 结构验收、两轮单次调用失败直出和两阶段端到端编排。真实模型推理与完整回归在服务器执行。
