# 服务器环境搭建指南

本文只说明当前 Demo 的服务器环境、依赖和模型准备方式。当前环境事实与风险由 `docs/02_服务器环境分析.md` 维护，业务运行方式见 `docs/04_业务代码运行与验证指南.md`。

## 1. 创建项目环境

```bash
cd /root/autodl-tmp/Collection-Demo

conda env create \
  -p "$PWD/.conda/envs/object-memory-demo" \
  -f environment.yml

conda activate "$PWD/.conda/envs/object-memory-demo"
```

项目使用 Python 3.12。环境放在项目内的 `.conda/`，但不进入 Git。

## 2. 安装运行依赖

```bash
python -m pip install -r requirements.txt
python -m pip install --no-deps -r requirements-sam3.txt
```

`requirements.txt` 固定 PyTorch、Transformers、Qwen 工具和通用运行依赖；`requirements-sam3.txt` 只固定 SAM3 源码版本，模型 checkpoint 不由依赖安装下载。

Web 实验台所需的 FastAPI、Uvicorn 和 multipart 上传解析也固定在 `requirements.txt` 中，不需要安装 Node.js 或单独构建前端。

依赖文件没有变化时不要重复安装。

## 3. 准备模型

SAM3 checkpoint：

```text
weights/sam3/sam3.pt
```

Qwen 使用项目数据盘中的 Hugging Face 缓存：

```bash
export HF_HOME="$PWD/weights/qwen"
export HF_HUB_CACHE="$HF_HOME/hub"
```

默认模型为：

```text
Qwen/Qwen3-VL-8B-Instruct-FP8
```

DINOv3 使用固定本地快照：

```text
模型：facebook/dinov3-vitb16-pretrain-lvd1689m
revision：5931719e67bbdb9737e363e781fb0c67687896bc
目录：weights/dinov3/dinov3-vitb16-pretrain-lvd1689m
```

首次下载前，先在模型页面接受访问条款并完成 Hugging Face 登录，然后执行：

```bash
hf download facebook/dinov3-vitb16-pretrain-lvd1689m \
  --revision 5931719e67bbdb9737e363e781fb0c67687896bc \
  --local-dir weights/dinov3/dinov3-vitb16-pretrain-lvd1689m
```

运行时只读取该目录，不联网补文件。至少确认以下文件存在：

```bash
test -f weights/dinov3/dinov3-vitb16-pretrain-lvd1689m/config.json
```

模型权重、token 和缓存不进入 Git。

## 4. 检查服务器环境

```bash
python scripts/check_server_env.py \
  --model-dir weights \
  --data-dir data \
  --sam3-checkpoint weights/sam3/sam3.pt \
  --dinov3-model-dir weights/dinov3/dinov3-vitb16-pretrain-lvd1689m \
  --output environment/server_env_report.json
```

环境检查覆盖 Python、PyTorch、CUDA、GPU、磁盘、关键包、SAM3 checkpoint 和 DINOv3 本地快照目录。它不运行正式图片推理。

## 5. 运行前确认

- 当前终端已激活项目 Conda 环境；
- `nvidia-smi` 能看到目标 GPU；
- SAM3 checkpoint 文件存在；
- DINOv3 固定快照目录存在且包含 `config.json`；
- `HF_HOME` 与 `HF_HUB_CACHE` 指向项目数据盘；
- `data/input/` 与选定的记忆根目录彼此独立；
- 新的全量比较运行使用新的空记忆根，避免旧哈希直接跳过输入。

## 6. 准备 Web 实验台访问

Web 服务默认监听 `127.0.0.1:6006`。`127.0.0.1` 表示只接收服务器本机上的连接，`6006` 才是端口；通过 SSH 隧道访问时可以保持这一设置。

AutoDL 的自定义服务会把实例内的 `127.0.0.1:6006` 或 `127.0.0.1:6008` 映射为平台提供的公网 HTTPS 地址。这个地址可能被其他电脑访问，因此使用自定义服务时，无论程序监听 `127.0.0.1` 还是 `0.0.0.0`，都必须先设置至少12字符的 Basic 密码：

```bash
export OBJECT_MEMORY_WEB_PASSWORD='<设置一个至少12字符的强密码>'
```

然后仍可使用更收敛的监听地址启动：

```bash
python scripts/run_object_memory_web.py --host 127.0.0.1 --port 6006
```

可选用户名环境变量为 `OBJECT_MEMORY_WEB_USERNAME`，默认值是 `object-memory`。密码只通过服务器环境变量提供，不写入仓库、命令参数或浏览器代码。Basic 认证必须配合 SSH 隧道或 AutoDL 的 HTTPS 自定义服务入口使用，不应把原始 HTTP 端口直接暴露到公网。若只是停止使用密码，可在停止 Web 服务后执行 `unset OBJECT_MEMORY_WEB_PASSWORD`；这只会移除当前 shell 中的环境变量，不会改变监听地址或端口。

Web 进程必须保持单 worker；项目入口已固定这一点。同一实例只允许一个活跃实验。当前流程按 `SAM3 → DINOv3 → Qwen3-VL` 分阶段顺序加载并释放模型：先完成全部图片的自动点网格分割，再完成全部候选的视觉指纹与聚类，最后执行聚类级语义审查。仍需通过服务器回归测试和正式运行确认三个阶段的实际显存峰值与总耗时。
